# 中医知识蒸馏与智能体平台终极需求

## 1. 产品目标

建设可独立运行的中医知识蒸馏、知识包管理和临床推理支持平台。平台把教材、论文、医家经验、医案和授权病例转换为有来源、有版本、可审计、可组合、可查询的数据，并由受控 Agent 调用已验收 Skill 完成分析、复核和安全治理。

当前研发以中医为主。西医只保留通用医学主干、医学体系标识、版本化 Profile 和未来接口位置，不建设西医专业知识与推理能力。

产品运行不能依赖 Codex 或其他编程智能体。Codex 只用于开发和维护。

## 2. 两条业务主线

### 数据生产

```text
原始材料
→ 文件识别/OCR与原文定位
→ 中医知识或病例候选
→ 证据、缺口、冲突和审核状态
→ 知识包构建与校验
→ 安装、组合、版本更新和回滚
```

### 数据消费

```text
患者授权信息与多轮回答
→ 标准病例状态
→ 多维检索与局部知识图
→ 多个辨证候选的支持/反证/冲突
→ 高信息量且安全的下一问
→ 停止条件
→ 有证据、不确定性和安全状态的候选结论
```

生产和消费必须同时可验证。不能只生成包而不能查询，也不能让问诊依赖包外隐藏知识。

数据层与思维层的主体职责和业务代码逻辑分开，公共基础设施可以共用：数据层提供生产、包管理、校验、基础检索和复核，思维层通过这些接口实施病例驱动的检索策略、联想与推演。共享Schema、模型适配、存储、注册表和运行时不违反分层；不要求严格的进程、部署或故障隔离。修改思维逻辑应保持数据功能和旧包兼容，具体边界见md/02-整体技术架构.md。

## 3. 中医数据核心

知识覆盖五类：

1. 中医基础理论；
2. 中药；
3. 辨证；
4. 方剂；
5. 临床病例与结局。

基础理论是辨证基础，辨证是治法与方药候选基础，但各类数据保持自身语义、证据和适用条件，不能压成“能治什么病”的扁平表。

分类采用多维视图：来源类型、知识类型、中医层次、证据状态、适用主题、审核/治理状态和字段身份。事实层只有一份；分类和索引可从事实重建。

俗语、短文和非正式经验材料也可作为来源保存原话、作者或未知归属、获取位置与审核状态，便于人工纠错；不得因收录就升级为教材结论、临床疗效或已验证知识。

## 4. 地图式多轮辨证

思维层实现受用户设计确认门约束：正式开始新增或实质扩展前必须停止并询问用户是否确认本次设计，明确确认后才实现或委派。通用“继续”不代表确认；规则详见《规则与变更策略》的“思维层实现前的用户设计确认门”。确认前可完善设计，独立数据层任务可继续。

问诊不是一次关键词匹配，而是候选状态机：

1. 根据当前病例状态召回相关种子节点；
2. 只扩展受限局部知识图；
3. 同时维护多个证候、病机和治法候选；
4. 记录支持、反证、冲突、缺失和未采用分支；
5. 选择信息增益高且安全的问题；
6. 每轮保存包版本、召回范围、候选变化、剪枝和停止依据；
7. 输出候选而非伪造确定诊断，并经过安全门。

具体评分、图深度、剪枝和停止参数必须通过阶段04评测后确定。

## 5. Agent 职责

- `OrchestratorAgent`：目标识别、任务状态、Skill 调用和失败恢复；
- 数据分析 Agent：材料摄取、分析、检查点和知识包生产；
- `TCMReasoningAgent`：中医四诊、病机、证候、治法和候选更新；
- `EvidenceReviewAgent`：证据、反证、冲突、缺失和一致性检查；
- `SafetyGovernanceAgent`：红旗、隐私、版权、处方和高风险阻断。

职责不等于必须使用五个模型或进程。只有独立权限、状态、工具或评测需求成立时才拆分 Agent。`WesternReasoningAgent` 是未来名称，不属于当前实现。

## 6. Skill 家族

当前定义十类：材料摄取、证据定位、知识蒸馏、病例蒸馏、中医推理、安全门、方剂、知识包构建校验、知识包查询、质量评价。Skill 必须可注册、版本化、调用和测试，并声明输入、输出、权限、错误与证据要求。

Agent 只能调用已经实现、登记并验收的 Skill。不得先生产正式数据，再补 Skill、Schema 或验证器。

## 7. 数据与证据规则

- 原文、OCR、纠正候选、模型分析、用户更正和专家确认分开；
- 每个医学事实指向来源与位置；
- 相同知识在不同来源保持独立节点，通过地址和候选关系连接；
- 疗效必须区分来源主张、真实观察和模型预测；
- 不确定、缺失和不适用不能写成否定；
- 字段、分组、节点和单元四级失败隔离，但不能静默修正医学值；
- 历史治疗不是现代建议，反事实不是现实结局。

## 8. 最终平台能力

- 多格式摄取、断点恢复、失败重试和审计；
- 单文件知识包的构建、校验、安装、停用、升级、卸载和回滚；
- 多包全文、字段、图和未来向量联合检索；
- LadybugDB 可重建工作库；
- 地图式中医多轮辨证和安全协作；
- 专家评审、版本比较、评价和监控；
- MCP、REST、必要 SDK 和 Web 界面；
- 受控后训练数据视图和发布门。

“自我丰富”指在授权范围内调用既有 Skill 学习新资料、复用当前知识包和相关记忆、形成可追溯候选，再通过校验与审核发布；不等于自主改写代码、绕过安全门或未经评审修改模型权重。会话、用户偏好与患者临床资料分域管理，记忆必须可查看、更正和删除，不得覆盖当前证据。

## 资料补充与执行自主性

工程任务按当前设计和正式任务连续推进，可自行补齐范围内的代码、测试、依赖和文档，不以旧数据包待用户后补为通用阻塞。确需新增知识或候选训练数据时优先利用现有PDF，先核对来源指纹与覆盖台账，避开已有有效成果或待补包记录覆盖的页，不重复付费蒸馏。后补包只读核验后接入，不覆盖现有来源。

自主推进不允许伪造专家审核、医学金标准或资料许可。正式后训练仍受质量、用途、环境、成本和发布门约束，知识蒸馏不等于权重训练。既有页码和用途外发许可不静默扩大；本地工程与不需新资料的分析先行，不为索要暂不需要的文件停止工作。

## 9. 不可破坏边界

数据层默认保持当前包结构兼容。推理链、Agent工作流及产品能力变化应优先通过运行时、独立会话或可重建视图承载，不要求重打旧包或重复蒸馏。必要且无法由兼容扩展解决的结构变化，必须有明确事实/完整性依据及版本、旧包兼容、迁移/回滚和验收方案；来源推理片段不能被新运行时推理覆盖。现有协议仍属实验版本，此约束是兼容承诺，不冒称正式包v0已完成。

- 安全门优先于专业推演；
- Agent 不直接修改正式数据库；
- 知识包不携带任意可执行代码；
- 患者资料必须授权、最小化和去标识化；
- 软件校验不等于医学验收；
- 后训练不能替代知识包、检索、规则、评审和安全；
- 目标能力不得冒充当前实现。
