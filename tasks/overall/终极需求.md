# 中西医知识蒸馏与智能体平台终极需求

## 1. 最终目标

建设一套可独立运行的中西医知识蒸馏、知识包管理和临床推理支持平台。平台能够把教材、论文、指南、医家经验、医案和临床病例转化为有来源、有版本、可审计、可组合和可调用的知识与病例过程数据，并由受控 Agent 调用可验证 Skill 完成构建、查询、推演、评审和安全治理。

当前研究和数据重点是完整的中医知识体系，包含基础理论、药材、辨证、方剂和临床案例，不能将基础知识缩成病机或辨证字段。平台底层保留通用医学主干与版本化西医扩展入口，本轮不扩充西医知识结构。

最终交付是独立可运行的智能体产品：一条主线接收各种受支持的资料，分析并持续更新可迁移知识包；另一条主线使用这些包开展有证据的问诊辅助。Codex 只参与开发，不是任何业务能力的运行依赖。其他未明确功能保留扩展点，不提前编造。

## 2. 最终业务闭环

```text
原始材料与病例
  → 可调用 Skill 解析和证据定位
  → 通用医学对象与专业对象
  → 标准病例与临床认知图
  → 知识包构建和校验
  → LadybugDB 联合工作库
  → 查询与中西医并行推演
  → 安全门与人工评审
  → 状态轨迹、评价和版本更新
```

生产端和消费端必须同时成立。平台不能只生成知识包而没有查询和使用能力，也不能让查询端依赖未声明的包外说明或提示词。

## 3. 最终 Agent 体系

基线定义六类逻辑 Agent。它们是职责，不要求对应六个模型或六个进程：

1. **OrchestratorAgent**：识别任务、选择专业路径、调用 Skill、管理状态、处理失败并汇总结果；
2. **数据分析 Agent**（原 KnowledgeBuilderAgent 职责）：接收文件，组织识别/OCR、知识与病例分析、断点续跑、可迁移包构建更新和检查；知识蒸馏 Skill 是其内部工具，完整能力按端到端结果验收；
3. **TCMReasoningAgent**：处理中医四诊、病机、三层对齐、证候、治法、方剂、药物和针灸路径；
4. **WesternReasoningAgent**：处理标准表型、病理生理、诊断依据、鉴别、检查、风险、干预和预后路径；
5. **EvidenceReviewAgent**：独立检查支持、反证、缺失、冲突、来源、证明图、格式和一致性；
6. **SafetyGovernanceAgent**：执行红旗、权限、隐私、版权、处方、禁忌、发布与高风险阻断。

初始实施不同时启用六个 Agent。Skill 基础未稳定前不实现多 Agent；最小编排从 OrchestratorAgent、KnowledgeBuilderAgent 和 EvidenceReviewAgent 三个逻辑角色开始。其他角色达到对应阶段门后启用。新增 Agent 必须证明存在独立权限、状态、工具、并行吞吐或评价需求。

## 4. 最终 Skill 体系

2026-10-15 再次澄清：总智能体委派资料处理小智能体，调用产品自带多格式识别、OCR、内容分析、持久化断点和包更新能力。首批 PDF、DOCX、TXT/Markdown、PNG/JPEG，其他格式按适配器扩展。200 页书在第 100 页暂停后，关闭程序重启仍从未完成阶段继续。完成包放在统一目录自动发现，复制到另一台兼容产品即可查询，不依赖原始文件、旧任务或 Codex。T02-P 先验收工具链再接最小父子入口；完整问诊仍分阶段完成。详见 `md/16-PDF资料处理与数据包更新.md`。

基线定义十一类核心 Skill 家族。具体知识包或方剂可以产生多个实例，但不改变家族数量：

1. **MaterialIngestionSkill**：登记文件、解析版面、OCR、分段、表格与图片恢复；
2. **EvidenceGroundingSkill**：形成原文证据、位置、纠正候选、来源主体和证据质量；
3. **KnowledgeDistillationSkill**：从材料形成通用知识对象、关系、来源推理片段和专业扩展候选；
4. **CaseDistillationSkill**：完成 RawCase 到 CanonicalCase、诊次、观察、时间线和病例轨迹候选；
5. **TCMReasoningSkill**：完成四诊、病机、主次兼夹、三层对齐、证候、治法和经典方法路由；
6. **WesternReasoningSkill**：完成表型、病理生理、诊断、鉴别、检查、风险、干预和预后分析；
7. **SafetyGateSkill**：识别红旗与越权风险，产生阻断、降级、检查、转诊或复核要求；
8. **FormulaSkill**：以方剂为组合能力，包含统一药物层、配伍、剂量、炮制、加减、停调和状态变化；
9. **KnowledgePackageBuildValidateSkill**：封装、校验、版本化知识包并生成质量报告；
10. **KnowledgePackageQuerySkill**：安装后查询知识、病例、路径、来源、冲突和状态，验证知识包可用性；
11. **QualityEvaluationSkill**：执行结构、证据、医学、安全、回归和跨版本评价。

Skill 家族内部可以包含普通函数、规则、模型调用、工具和子流程，不要求每个内部步骤都成为顶层 Skill。所有 Skill 必须可注册、可调用、可版本化、可测试，并声明输入、输出、错误、权限和证据要求。

## 5. 最终数据产物

- 项目级统一知识包协议；
- 来源、证据、知识、关系和推理对象；
- RawCase、CanonicalCase、Encounter 和状态轨迹；
- 中医病机三层结构与西医专业路径；
- 证明图、支持、反证、缺失和冲突对象；
- 目标、治疗算子、历史行动、候选行动和响应；
- FormulaSkill、HerbKnowledge、FormulaHerbRole 和控制规则；
- 评审、错误、版本、许可、隐私和数据血缘；
- 可重建的评测与未来训练任务视图。

## 6. 最终平台能力

- 材料摄取、断点恢复和错误记录；
- 单包构建、校验、安装、启用、停用、升级、卸载和回滚；
- 多包联合检索、图查询、全文检索和向量召回；
- 中医、西医和安全路径并行；
- Web、MCP、REST API 与必要 SDK；
- Agent 与 Skill 调用审计；
- 专家评审台和版本比较；
- 多环境适配；
- 评测、规模测试、监控和受控后训练。

## 7. 不可破坏的规则

- 原文、纠正、模型候选和专家确认分开；
- 中医与西医共享事实但不强行统一理论；
- 安全门优先于专业推演；
- Agent 不直接修改正式数据库；
- Skill 不保存未声明的医学事实；
- 知识包不携带任意可执行代码；
- 历史治疗不等于现代推荐；
- 反事实和预测不等于真实疗效；
- 正式蒸馏开始前，生产 Skill、校验 Skill 和查询 Skill 必须通过闭环验收；
- 后训练不能替代知识包、检索、规则、评审和安全。

## 8. 可调整空间

稳定契约包括来源、证据、版本、医学体系、审核、安全和数据身份。可调整内容包括具体算法、模型、字段物理布局、Agent 部署方式、Skill 内部实现、向量模型、前端框架和性能参数。任何调整不得破坏稳定契约和已发布包的可迁移性。
