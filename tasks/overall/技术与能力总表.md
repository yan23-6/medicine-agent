# 技术与能力总表

本表区分已固定方向、当前建议和延期决策。当前项目只有文档，表中的技术均不代表已经安装或实现。

## 1. 技术基线

| 领域 | 当前选择 | 状态 | 用途与约束 |
| --- | --- | --- | --- |
| 核心运行时 | CPython 3.13 + uv | T01 accepted | `uv` 管理解释器、虚拟环境与锁文件；阶段 03 接入 LadybugDB 前重新验证兼容范围 |
| 数据契约 | Pydantic 2 系列 + 导出 JSON Schema | T01 accepted | Pydantic 负责 Python 运行时模型，JSON Schema 提供语言无关契约与兼容检查 |
| 交换数据 | JSON/JSONL + manifest | provisional | 便于流式写入、版本比较和人工检查；正式包封装在阶段 03 冻结 |
| 图数据引擎 | LadybugDB | fixed direction | 嵌入式联合工作库；知识包本身不是 LadybugDB 文件 |
| 全文与向量 | LadybugDB 扩展或受控适配层 | deferred | 在真实数据和发行环境中验证后确定 |
| 服务接口 | MCP + REST API | fixed direction | MCP 服务智能体，REST 服务程序和兼容环境；具体 SDK 在阶段 05 确定 |
| Web | 待选 | deferred | 先完成核心服务与接口，再选择前端框架 |
| LLM | 提供商无关接口 + FakeModel + OpenAI-compatible 适配器 | T01 accepted | 离线测试不需要密钥；真实调用使用本地忽略配置并脱敏记录调用元数据 |
| 测试 | pytest 单元、契约、集成和显式在线冒烟测试 | T01 accepted | 默认测试离线；在线测试仅在用户配置真实 API 后显式执行 |
| 工作流 | 显式状态机 + 可重跑任务 | fixed principle | 支持断点、幂等、失败隔离和版本追踪 |
| 部署 | 本地优先、无外部数据库服务 | fixed principle | 默认不要求 Docker 或独立数据库；机构部署可增加可选模式 |

## 2. 能力实现顺序原则

- 先建立可调用 Skill 协议和最小生产消费闭环；
- 再实现中医专业蒸馏与病例推理；
- 知识对象稳定后冻结实验知识包物理格式；
- 知识包通过查询 Skill 验证后再导入 LadybugDB；
- Skill 稳定后才加入 Agent 编排；
- 单一闭环通过后才扩大材料、专业和客户端范围；
- 后训练最后进入，不为补救 Schema 或 Skill 缺陷而提前训练。

## 3. Skill 实现形式要求

每个 Skill 包至少包含：

- manifest 或等价身份声明；
- 人类可读说明；
- 输入和输出 Schema；
- 调用入口；
- 实现代码、规则或工具引用；
- 依赖和权限声明；
- 错误码与失败语义；
- 证据、审核和安全要求；
- 测试夹具与验收用例；
- 版本与变更记录。

`SKILL.md` 可以作为说明和调用指导，但不能单独证明 Skill 可执行。只有调用入口、实现和测试共同存在时，状态才能标记为已实现。

## 4. Agent 与 Skill 的关系

Agent 读取任务状态并调用 Skill；Skill 返回结构化结果；确定性平台服务完成持久化、版本和发布。不得把数据库写入、版本切换或包发布交给模型自由决定。

```text
Agent
  → Skill Registry
  → Skill Runner
  → Schema Validation
  → Candidate Store
  → Review Gate
  → Versioned Publish Service
```
