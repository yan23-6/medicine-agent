# B10 覆盖管理契约与失败边界

## 设计决定（实现前确定）

新增独立管理契约 `coverage/0.1.0`，Pydantic 为唯一结构来源，导出到 `schemas/coverage/`。不改变实验 medpkg、医学注册表、既有 Schema 或 Skill 版本；不新增 Agent/Skill，不接入自动派发。API `CoverageService.inventory()` 与 `plan(request)`，CLI `analyze coverage`，仅写独立工作区的可重建解包缓存，不能调用会写包目录的 prepare/scan/view。

身份按原件 SHA256，不按书名。单位显式区分 physical_page、text_line、structured_unit、image、unknown；PDF 的 page 是从1开始的物理页，不以印刷页代替。范围在契约中用有界、排序去重的单元列表表达，文档总单元数独立记录。阶段为 extraction（原文提取/OCR，不保证识字正确）和 semantic_candidate（中医语义分析已提交，不保证内容完整或医学正确）。无医学审核/金标准完成阶段。

每条覆盖记录保存来源、单位、总数、阶段、状态、策略、包/组件/父修订/家族地址、资源及完整性依据。只有全包通过既有校验、来源指纹与稳定source_id吻合、revision范围和processing_scope/ownership一致、位置与单位一致，才可声明已校验范围。缺可选元数据为unknown，不凭tcm.json存在宣称整页完成。语义完成要求已校验逐单元ownership提交记录及非空语义节点；仅旧revision+证据可证明提取阶段，语义范围待核。gap/拒绝项不触发重做整页。

## 状态与规划

覆盖状态 verified、historical_pending、unknown、partial_failed；策略比较在规划中给出 incompatible_policy。历史声明显式输入，未恢复绝不计为verified。无指纹的声明进入独立待核列表，不按标题绑定任意来源；已知指纹的未知范围保守阻止该来源自动建议，不能影响别的来源。

请求指定来源指纹、单位类型、总数、单元范围和语义策略（默认 source-faithfulness-v3 / previous-unit-plus-current-v1 / 0.3.2）。提取可独立复用；语义缺策略为POLICY_UNKNOWN，策略不同为INCOMPATIBLE_POLICY，不自动重蒸馏。提取记录另存方法及适配器版本；策略字段不输出模型配置或endpoint。已停用组件只提供历史暂避依据，不冒充当前有效版本；同一家族多活修订（包ID或manifest哈希不同）须待核选择，不拼接不相交的修订范围。跨独立家族的同源同阶段记录可共同提供结构覆盖，绝不合并医学事实。

对每个请求单元分别给出 covered、held、needs_check、proposed：完整有效阶段排除；历史待补暂避；缺字段/单位或总数冲突/不兼容策略待核；其余仅建议最早缺失阶段。提取完成但语义缺失只建议语义，不建议重新OCR。计划不是任务执行许可，也不复用原任务缓存代替新任务的上下文/配置检查。

## 隔离与确定性

逐文件验证，任何完整性、身份、来源失败隔离整个文件，该文件的部分记录不进入覆盖；其他文件继续。范围越界、非整数、包内重复单元和位置单位混淆报告错误，不截断修补；请求/历史范围及重复声明则确定性排序去重。可选字段缺失保持unknown。根目录不存在/不可读、坏包和不明历史声明都在报告保留，未盘点文件不得被误判为没有成果；无法确认来源的坏包使新增建议降级待核。不明指纹历史只进入独立待核索引，不凭名称阻断别的来源。

目录输入排序、记录按规范JSON排序去重，无时间戳；逐文件前后哈希一致才提交记录。相同输入重复执行及历史输入顺序变化结果一致。历史声明本身须通过请求Schema；不合法管理请求整体拒绝，包内缺字段和坏文件则局部隔离。

## 验收边界

合成软件夹具覆盖所有失败/重叠/策略/确定性分支；真实验收只读B7包，不解析原PDF，不调用模型。对34—38页须证明两阶段覆盖，包哈希、188证据与unreviewed不变。不能把本工具当医学审核、整书调度、训练、发布或数据库能力。
