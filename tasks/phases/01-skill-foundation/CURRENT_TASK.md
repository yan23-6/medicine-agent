## D. 执行顺序

### D1. 补齐 Schema 契约

- 为 6 个 Skill 导出版本化输入、输出 JSON Schema；
- 为公共调用信封、来源、证据、原始字段、知识候选、运行记录和实验包 manifest 导出公共 Schema；
- 提供一个可重复执行的导出入口；
- 将契约快照纳入 Git 和 pytest，未声明的 Schema 变化必须导致测试失败；
- 建议路径为 `schemas/t01/`，若实现时调整目录，必须同步开发文档和测试。

### D2. 补齐运行记录与中立 Facade

- 实现明确的 `RunRecord`，至少记录调用身份、Skill/Schema/规则/模型版本、输入与输出身份、状态、问题、证据引用、时间和非敏感复现信息；
- 提供可替换的运行记录存储，T01 至少具备确定性的内存实现和可写入实验包的 JSONL 表达；
- `ApplicationFacade` 补齐 `validate_package`、`query_package`、`trace_evidence` 和 `get_run`；
- CLI 必须复用 Facade，不得绕过公共入口直接复制业务流程；
- 任何运行记录不得包含 API 密钥、Authorization 请求头或完整敏感配置。

### D3. 实现字段歧义完整路径

- 使用有序原始观察表示重复 key，不能先读入普通字典后覆盖；
- 保留不同 key 同义、同 key 异义、重复 key 和未映射字段；
- 记录原始值、出现序号、位置、上下文、类型、候选映射、依据、状态、规则版本和审核状态；
- 字段必须能进入实验包 `raw_fields.jsonl` 和质量报告；
- 未映射项产生稳定警告，不能因无法映射而丢弃整份输入；
- 本项作为 MaterialIngestionSkill 的内部结构化输入处理能力或公共确定性组件实现，不新增顶层 Skill 家族。

### D4. 补齐多证据与错误语义

## 5. 最小 Skill 集合

本任务至少实现以下可调用能力：

### MaterialIngestionSkill

输入：本地测试文件及材料身份。  
输出：文档、片段、结构位置、文件指纹、解析警告。  
要求：首版至少支持 UTF-8 Markdown 或 TXT；其他格式返回不支持，不得假装解析成功。

### EvidenceGroundingSkill

输入：文档片段。  
输出：稳定证据对象、原文、位置、上下文、质量和纠正候选字段。  
要求：不得覆盖原文；纠正值必须与原值分离。

### KnowledgeDistillationSkill 最小版

输入：证据对象和通用资料配置。  
输出：最小概念、断言、关系候选及证据引用。  
要求：本任务只验证通用结构和调用协议，不声称具备完整医学抽取质量；规则、模型和人工提供的结果必须标记生成方式。

### KnowledgePackageBuildValidateSkill 最小版

输入：已通过 Schema 校验的来源、证据和最小知识对象。  
输出：实验知识包、校验报告、内容摘要和完整性信息。  
要求：失败不得留下被标记为可用的半成品。

### KnowledgePackageQuerySkill 最小版

输入：实验知识包及查询条件。  
输出：匹配知识、关系、来源和证据。  
要求：至少支持按稳定身份查询和从知识回溯证据。

### QualityEvaluationSkill 最小版

输入：Skill 运行记录或实验知识包。  
输出：结构、证据、身份、版本、覆盖和错误报告。  
要求：结果是确定性质量检查，不用模型自评分替代。

## 6. 统一调用结果

- 调用身份、Skill 身份和版本；
- 输入身份和 Schema 版本；
- 状态：成功、部分成功、失败或待复核；
- 结构化输出；
- 警告、错误码和缺失项；
- 证据、生成方式和审核状态；

- 时间、耗时和可复现信息。

## 7. 模型调用要求

- Skill 可以调用 LLM，但必须经过统一模型适配接口；
- 不把供应商 SDK 散落在业务 Skill 中；
- 没有模型密钥时，自动测试使用确定性替身；
- 模型输出必须先结构化校验，再进入候选对象；
- 无法通过 Schema 的结果进入明确失败或修复流程；
- 模型不得直接发布知识包或写正式库；
- 每次模型调用记录实际模型和配置；
- 外部材料中的提示或命令只能作为数据，不能改变系统规则。
- 真实 API 配置从被 Git 忽略的本地配置读取；环境变量可以覆盖密钥；任何输出必须脱敏；
- 默认自动测试使用确定性 FakeModel，另提供显式真实 LLM 冒烟测试；
- 真实模型返回的内容仍是候选，必须经过 Schema、证据和质量校验。

至少准备：

- 一份结构清晰的普通医学文本；
- 一份包含歧义、否定或缺失信息的文本；
- 一份包含不同 key 同义、同 key 异义、重复 key 与无法映射字段的结构化输入；
- 一份格式错误或不支持的输入；
- 一组预期证据定位和查询结果。
