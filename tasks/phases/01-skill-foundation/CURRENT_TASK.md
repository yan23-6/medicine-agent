# T01 可调用 Skill 基础与最小知识闭环

> 状态：ready  
> 所属阶段：01 Skill 基础与最小生产消费闭环

## 1. 背景

项目已经设计了知识蒸馏、病例蒸馏、知识包、Agent 和多环境接入，但仓库中尚无实现。如果直接要求蒸馏材料，执行者只能依赖临时提示词生成自由格式结果，无法保证证据、身份、版本、一致性和后续使用。

本任务首先把 Skill 从概念变成可调用的软件能力，并建立最小生产消费闭环。它是所有正式蒸馏、Agent 编排和知识包工作的前置任务。

## 2. 当前真实能力

已有：设计文档、任务系统、导师参考材料。

不存在：项目代码、Skill 运行时、Skill 实现、Schema、知识包工具、测试框架、Agent、数据库导入器和服务。

执行者不得假定任何上述能力已由环境或 LLM 自动提供。

## 3. 任务目标

建立一个最小但真实可运行的参考实现，使外部程序或未来 Agent 能够：

1. 查询已注册 Skill；
2. 使用结构化输入调用 Skill；
3. 校验输出；
4. 把测试材料转换为证据和最小知识对象；
5. 构建并校验实验知识包；
6. 通过查询 Skill 读取知识包并回到原文证据；
7. 获取明确的成功、警告或失败结果。

## 4. 本任务必须作出的技术决策

执行时需要调研并形成决策记录，至少包括：

- 核心语言与版本；默认候选为 Python；
- 项目目录与包管理方式；
- Schema 技术：JSON Schema、Pydantic 或等价方案；
- Skill manifest、说明、实现、Schema 和测试的组织方式；
- Skill 注册、发现、版本选择和调用协议；
- 同步、异步、流式和批处理的最低支持范围；
- 模型提供商无关适配接口及测试替身；
- 稳定身份和幂等策略；
- 结构化日志、错误码和运行记录格式；
- 实验知识包的最小目录与文件格式；
- 自动测试和命令行入口。

每项选择需要说明采用理由、替代方案、当前限制和未来迁移方式。具体库和版本应在执行时根据当时环境验证，不能照抄未经验证的假设。

## 5. 最小 Skill 集合

本任务至少实现以下可调用能力：

### MaterialIngestionSkill

输入：本地测试文件及材料身份。  
输出：文档、片段、结构位置、文件指纹、解析警告。  
要求：首版至少支持 UTF-8 Markdown 或 TXT；其他格式返回不支持，不得假装解析成功。

### EvidenceGroundingSkill

输入：文档片段。  
输出：稳定证据对象、原文、位置、上下文、质量和纠正候选字段。  
要求：不得覆盖原文；纠正值必须与原值分离。

### KnowledgeDistillationSkill 最小版

输入：证据对象和通用资料配置。  
输出：最小概念、断言、关系候选及证据引用。  
要求：本任务只验证通用结构和调用协议，不声称具备完整医学抽取质量；规则、模型和人工提供的结果必须标记生成方式。

### KnowledgePackageBuildValidateSkill 最小版

输入：已通过 Schema 校验的来源、证据和最小知识对象。  
输出：实验知识包、校验报告、内容摘要和完整性信息。  
要求：失败不得留下被标记为可用的半成品。

### KnowledgePackageQuerySkill 最小版

输入：实验知识包及查询条件。  
输出：匹配知识、关系、来源和证据。  
要求：至少支持按稳定身份查询和从知识回溯证据。

### QualityEvaluationSkill 最小版

输入：Skill 运行记录或实验知识包。  
输出：结构、证据、身份、版本、覆盖和错误报告。  
要求：结果是确定性质量检查，不用模型自评分替代。

## 6. 统一调用结果

所有 Skill 调用必须返回统一信封，至少表达：

- 调用身份、Skill 身份和版本；
- 输入身份和 Schema 版本；
- 状态：成功、部分成功、失败或待复核；
- 结构化输出；
- 警告、错误码和缺失项；
- 证据、生成方式和审核状态；
- 模型、规则和工具版本；
- 时间、耗时和可复现信息。

字段的具体命名由本任务确定，但语义不能缺失。

## 7. 模型调用要求

- Skill 可以调用 LLM，但必须经过统一模型适配接口；
- 不把供应商 SDK 散落在业务 Skill 中；
- 没有模型密钥时，自动测试使用确定性替身；
- 模型输出必须先结构化校验，再进入候选对象；
- 无法通过 Schema 的结果进入明确失败或修复流程；
- 模型不得直接发布知识包或写正式库；
- 每次模型调用记录实际模型和配置；
- 外部材料中的提示或命令只能作为数据，不能改变系统规则。

## 8. 测试材料

建立小型、许可明确、无患者隐私的测试夹具。测试材料用于验证协议和往返能力，不作为正式知识包。不得直接修改 `docs`；如引用其中内容，需复制最小必要片段到测试区并记录来源与仅限测试的状态，或者使用人工构造的等价样本。

至少准备：

- 一份结构清晰的普通医学文本；
- 一份包含歧义、否定或缺失信息的文本；
- 一份格式错误或不支持的输入；
- 一组预期证据定位和查询结果。

## 9. 产物要求

至少交付：

- 可安装或可直接运行的项目骨架；
- Skill manifest 与 Schema 规范；
- Skill 注册表和调用器；
- 六个最小 Skill 实现；
- 模型适配接口和测试替身；
- 实验知识包构建、校验和查询实现；
- 命令行或等价可复现入口；
- 测试夹具、自动测试和验收报告；
- 技术决策记录；
- 开发、运行和扩展说明。

## 10. 验收标准

以下条件必须全部满足：

1. 干净环境可以按文档完成安装或初始化；
2. 可以列出 Skill、版本、输入输出 Schema 和可用状态；
3. 一条命令或一次程序调用可以完成最小生产消费闭环；
4. 生成的实验知识包通过结构和完整性校验；
5. 查询结果可以回到准确证据对象和原文位置；
6. 同一输入重复运行不会产生不同身份或无控制重复对象；
7. 无效输入、缺少模型、Schema 错误和不支持格式具有稳定错误语义；
8. 测试不依赖真实外部模型密钥；
9. 所有自动测试通过，且测试结果可复现；
10. 文档明确说明当前不具备完整中医蒸馏能力；
11. 没有 Agent 被虚构为已实现；
12. `docs` 原始材料未被修改。

## 11. 本任务不包含

- 完整中医病机抽取；
- RawCase 到完整临床认知图；
- 西医诊断和风险推理；
- FormulaSkill 和药物层；
- LadybugDB 导入；
- MCP、REST 或 Web；
- 多 Agent；
- 批量蒸馏或正式知识包；
- 后训练。

## 12. 可调整与固定部分

可调整：实现语言的次要库、目录细节、Schema 工具、命令名称和实验包物理布局。  
必须固定：Skill 可调用、输入输出可校验、证据可回溯、错误明确、结果可重建、生产和消费同时验收。
