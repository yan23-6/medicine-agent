## 1. 背景与任务定位

T01 已经提供可调用 Skill、版本化 Schema、运行记录以及实验包 Build、Validate、Query、Trace，但当前知识抽取只验证通用结构，不具备完整中医病例标准化和病机推理能力。

T02 的目标不是开始批量蒸馏，也不是一次实现导师材料中列出的全部临床和方剂能力，而是用一个窄专题完成首次“专业 Schema—人工金标准—两个顶层 Skill—自动评价—实验包往返”闭环。

## 2. 推荐首个专题

推荐选择“胸痹初诊病例中的气虚血瘀、阳虚和痰湿候选病机”。理由是：

- `docs/医案分析.docx` 提供一条包含四诊、时序、历史诊断、历史治疗、转录疑点和现代胸痛安全风险的完整初诊材料；
- `docs/病因病机学说.md` 含劳倦、阳虚、气虚、瘀血、气虚血瘀、痰饮、虚实夹杂和审证求因等对应教材内容；
- 单个病例即可验证原文保留、候选纠正、多证据、主次兼夹、反证缺失、矛盾、历史行动隔离和安全门兼容性；
- `docs/导师发送医案的skills.docx` 以泻肝汤为主题，与胸痹专题不宜混成同一金标准；其中“原文事实与模型解释分离、条件动作、停止规则、状态转移和方内药物角色”保留为后续 FormulaSkill 的设计输入。

若用户选择泻肝汤作为首个专题，则本任务必须改为方剂 Skill 闭环，并补充同主题病例；不能沿用当前病例任务规格。

2026-09-29 用户已确认采用本节推荐的胸痹气虚血瘀专题。所需书籍、篇章、顺序和材料门见 `SOURCE_PLAN.md`。

### 仍不存在

## 4. 本次顶层 Skill 边界

本任务只新增两个可注册顶层 Skill：

1. `case-distillation`：把人工登记的原始医案和原始字段转换为 CanonicalCase；保留原文、候选纠正、时序、诊次、观察、历史诊断、历史行动、不确定项和证据引用。
2. `tcm-reasoning`：基于 CanonicalCase 和已登记教材证据形成中医候选推理图；输出支持、弱支持、反证、歧义、缺失、主次兼夹、矛盾、状态与治疗目标，但不直接发布现代治疗建议。

导师材料中的 CaseCanonicalizer、四诊、经典方法、病机推断、矛盾求解、证候组合、证据核查、反事实等名称，先作为内部模块或数据任务，不注册为独立顶层 Skill。只有后续证明其需要独立权限、版本、复用或评价时再拆分。

方剂识别、方义、药物角色、加减、状态转移、停调、方剂选择和比较属于 FormulaSkill 家族，本任务只预留接口，不实现。

## 5. 数据契约评审基线

### CaseDistillationSkill 输入

- 来源与许可/使用范围声明；
- 原始医案文本或人工切分片段；
- 有序原始字段，允许重复 key、同 key 异义和未映射内容；
- 可选人工纠正候选，但不得覆盖原文；
- 调用目的、Schema 版本和证据定位。

### CanonicalCase 最低输出

- `case_id`、患者去标识信息和一个或多个 `encounters`；
- 主诉、现病史、既往处理、四诊、生命体征和时间事件；
- 每项观察的原文、规范候选、来源证据、确定性与审核状态；
- 历史诊断、历史治疗与现代建议严格分字段；
- 未映射内容、OCR/转录疑点、缺失项和质量警告；
- 输入、输出、Skill、模型和运行身份。

### TCMReasoningSkill 最低输出

- 通用链：Observation → Feature → Hypothesis → Pathomechanism → Contradiction → State → Goal；
- 中医专有层：病因、病位、病性、病机、证候和治法候选；
- 每个结论的支持、弱支持、反证、歧义、缺失和来源证据；
- `primary`、`secondary`、`concomitant`、`candidate` 等角色，不把候选写成定论；
- 来源明示、规则推导、模型候选和人工确认分层；
- 只允许可解释的等级置信度或有校准依据的分数，禁止把示例数字伪装成临床概率；
- 安全标志与阻断状态，但不在 T02 内假装完整 SafetyGateSkill 已实现。

TCMReasoningSkill 的调用还必须接收 `safety_context`：包含安全状态、状态来源、评估者和未完成要求。T02 不负责形成完整现代医学风险结论；当安全状态缺失、未评估或未清除时，Skill 只能生成研究性病机候选，不能生成可执行治疗建议。

## 6. 安全和历史病例约束

首个病例包含近期加重且放射的胸痛。T02 必须验证以下硬约束：

- 风险信号从原文中完整保留并可回溯；
- 历史针灸方案只能标记为 `historical_action`；
- 未通过独立安全门时，TCMReasoningSkill 不得输出可执行治疗推荐；
- 中医辨证路径可以继续作为研究候选，但必须与现代风险处置路径并行；
- 医案中的姓名、日期及其他潜在身份信息按本地实验数据处理，不进入公开夹具，除非用户明确确认已经去标识且允许使用。

T02 只定义 SafetyGate 的兼容字段和阻断协议；完整 SafetyGateSkill 仍按后续阶段评审，不能在本任务中隐式实现为自由提示词。

## 7. 金标准建议

第一轮只用于验证结构和评价方法，建议规模为：

- 1 条原始初诊医案，形成 1 个 CanonicalCase；
- 从教材中人工选取 6 至 10 个直接相关证据片段；
- 把同一病例拆成字段标准化、证据归属、病机候选、冲突判断、安全隔离等多个评价单元，但不得把它们伪装成多例病例；
- 另建 3 至 5 个最小负例或边界夹具，覆盖“小便黄直接等于热证”“转录疑点被静默纠正”“历史治疗被写成现代推荐”等错误。

金标准至少需要两层状态：`annotated` 和 `reviewed`。AI 可以生成标注候选，但不能单独把候选宣布为医学金标准。医学正确性必须由用户指定的人工或专家复核者签署；没有复核的内容只能称为“预期样例”。
