# 项目路线图

路线图描述依赖顺序，不代表未来能力已经实现。真实状态只看 `STATE.md` 和实际产物。

## 总依赖

```text
G0 运行与文档基线
  → G1 可迁移知识包生产消费闭环
  → G2 中医数据语义、真实材料与人工质量门
  → G3 正式包协议与联合存储
  → G4 地图式多轮辨证与安全协作
  → G5 方剂药物与产品接口
  → G6 规模评价、论文实验与受控后训练
```

## G0—G1：基础与实验闭环

状态：done。

已有注册表、Runner、Facade、10 个 Skill、多格式摄取、本地 OCR、持久化任务、候选知识、证据追溯、复核更正、增量组合和单文件 `.medpkg`。这些是实验候选能力，不等于医学金标准或正式发布。

## G2：中医数据与真实材料质量门

状态：in_progress。

固定目标：完整基础理论、辨证、药材、方剂、病例五类知识；多维分类；来源独立；字段级容错；真实教材与病例的人工复核。

B7限定五页真实闭环、B8质量门、B9语义约束优化、B10来源覆盖/增量规划和B11复核准备已验收；当前B12补准备快照校验、意见接入与分歧治理。人工金标准、病例医学确认、真实跨来源正例和规模性能仍缺。阶段完成门：代表材料闭环、医学评审规则、错误分类、可重复验收和必要性能门同时成立，不把软件覆盖、复核准备或用户意见视为医学审核或阶段02整体完成。

## G3：正式知识包与联合存储

状态：idea。

冻结正式包 v0、迁移/回滚和兼容策略；实现 LadybugDB 导入与重建、多包联合查询、热插拔、索引性能和损坏隔离。不得先建数据库再补 Schema 与验证器。

复用已有来源覆盖与后补包核验；迁移和索引变化不触发整书重蒸馏，不自动覆盖来源或升级审核状态。

## G4：地图式多轮辨证

状态：idea。

在正式可查询知识包、CanonicalCase、TCMReasoningSkill 和 SafetyGateSkill 成立后，实现候选状态机：局部图召回、支持/反证/冲突、信息增益追问、剪枝、停止条件和安全升级。中医为当前路线；西医只保留未来 Profile/接口位置。

## G5：方剂药物与产品接口

状态：idea。

实现药材、方剂、配伍、剂量、炮制、禁忌和状态变化；通过安全门后提供候选方案。随后开放版本化 MCP、REST、必要 SDK 和 Web 评审界面。

## G6：评价与后训练

状态：idea。

完成规模、性能、跨环境、医学、安全和消融评价。只有错误稳定归因到模型能力且数据许可允许时，才生成后训练方案；后训练不能替代知识包、检索、规则、评审和安全。

## 全程固定门

- 旧包后补不阻塞独立工程；新增资料优先现有PDF，按指纹、页范围和阶段排除重复工作，后补包校验接入，不覆盖事实；
- 原文、OCR、模型候选、用户更正和专家确认分层保存；
- 安全门优先于医学推演；
- 数据包不携带任意可执行代码；
- 任何已实现/已验证/已发布声明必须指向实际产物和检查结果；
- 原始 PDF、本地密钥和真实运行产物不进入 Git。
