# proposals — 待定候选设计输入

这个文件夹用来放**从原始材料里分析出来、但还没被用户确认的东西**：候选设计、结构映射、验收集、待核结论和开放问题。它相当于设计备忘录，不是规格书。

- **没有权威性**：这里的内容既不是当前实现，也不是 `md/` 稳定设计或 `tasks/overall/` 的最终需求。
- **不能照着写代码**：任何实现、原型、测试、派单都必须先经用户确认，再写入 `md/` / `tasks/` 后才能开始。
- **AI 读取前先看 [AGENTS.md](AGENTS.md)**：那里是硬性禁止条款，优先级高于本文件。

## 为什么单独建目录

`docs/` 是导师原始材料（只读），`md/` 是已确认设计，`tasks/` 是任务与状态。分析结论在确认前不属于其中任何一类；混进 `md/` 会被后来的 AI 当成已定设计，混进 `tasks/` 会被当成待执行任务。所以单列，并在目录级 AGENTS.md 里写清“待定”语义。

## 升格方式

1. 用户明确确认某提案的版本与范围；
2. 把结论写进 `md/`（稳定设计）或 `tasks/overall/`（能力口径）；
3. 同步 `STATE.md` / `HANDOFF.md` / `CURRENT.md`；
4. 才能开始实现或派单。

未确认前，本目录内容只能被引用、讨论和推翻，不能被实现。

## 目录内文件写法约定

每个文件开头写五行：状态、来源、日期、用途、不构成什么。数字结论标注实测来源，推测标注草案，原始材料与模型归纳分开写。
