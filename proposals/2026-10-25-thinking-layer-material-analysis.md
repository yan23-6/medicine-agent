# 思维层材料分析（候选设计输入）

> 状态：`draft / unconfirmed`。不构成实现、不构成稳定设计、不构成需求。
> 来源：`docs/思维发现.docx`（64 页扫描图，原书第 17–80 页）、`docs/名医文献思维构造结果样例(1).docx`（15 个知识单元的教学样例）。
> 日期：2026-10-25。
> 用途：为思维层设计提供候选骨架、结构映射、验收集与取舍依据，供用户讨论确认。
> 不构成：用户对思维层设计的确认、实现或派单授权、Schema/字段/包结构变更依据、医学正确性结论。

## 0. 结论摘要

1. 两份材料互补：样例回答“什么算一条可执行的中医知识”，书回答“这些知识怎样组织成思维过程”。单独任何一份都不足以支撑思维层。
2. 样例的核心不是内容，而是**条件绑定**：同方不合并、分支必须保留、加味/减味/改方/停服分开、归纳与原文分离。这恰是当前最缺的约束。
3. 书的核心是**可计算的组织形式**：概念对、概念层次与权重、思维序列、分析问题、分析主题、增量更新。可借结构，不能照搬它的单一层次假设、全路径枚举与阈值拍定。
4. 实测（附录 B）：现有真实包 63 节点/135 组/478 字段/188 证据，但**字段全部落在 `tcm_foundation` 一类、包内关系为 0**。思维层即使现在开工，也没有“选方条件/加减/停服/配伍”这几类可消费事实，也没有可遍历的关系边。
5. 因此顺序应为：数据层先具备条件级字段与关系（B20 及后续）→ 思维层才有输入；在数据未就绪前，思维层只适合做包外只读索引与结构验收集。

## 2. 样例给出的知识单元规范

### 2.1 五类可执行结构

| 类型 | 样例 | 结构要点 |
|---|---|---|
| 基本选方条件 | U01、U02 | 前提语境（太阳病）+ 症状组合 + 方剂；条件随条文走 |
| 条件分支 | U03 | 同一前提（下之后）下两个互斥走向：气上冲→可与；不上冲→不可与 |
| 适用限制 | U05 | 明确“不可与”的边界（脉浮紧、发热、汗不出），与可用条件并存而不互相覆盖 |
| 调整 | U06 加味、U08 减味后再加味、U09 改方 | 加 / 减 / 换分别建模，不合并为“调整”；U08 第二分支承接前文 |
| 停止条件 | U10 | 达到“一服汗出病差”即停后服，不产生疗程或剂量 |

### 2.2 三类组织关系

- **并列**：U01 与 U02 同涉桂枝汤但内容不同；V02–V04 三组药对并列，不能从行文顺序推出用药先后。
- **承接**：U08 中“若微恶寒者”承接同条前文，不能单独抽成“微恶寒即加附子”。
- **总述—分述—总结**：V01 提出整方认识，V02–V04 分述三组配伍，V05 回到整方评价。V01 与 V05 都提“三阴并治”，但一个是提出观点、一个是总结，故分别保留。

### 2.3 六条硬边界（建议原样继承到思维层规则）

1. 相同方名不合并：提到同一方剂不等于同一条知识。
2. 条件必须与单元绑定，分支必须保留（含禁止态）。
3. 加味、减味、改方、停服分开记录，不混为一种“调整”。
4. 归纳（学生概括/单元名）与原文（证据）分离，后者不可被前者替代。
5. 出处用篇章与起句定位，不另编条号；节选必须标注。
6. 不补原文没有的剂量、加减、病机和疗效结论；样例明确“未据此作临床疗效评价”。

## 3. 思维发现的可迁移模型

### 3.1 可借用

| 书中概念 | 可借用之处 | 备注 |
|---|---|---|
| 问题空间三要素（初始状态 / 目标状态 / 算子） | 把“问诊”形式化为在候选空间中搜索区分性观测 | 与 `md/07` 的“地图式多轮候选循环”同构 |
| 明确界定 / 未明确界定问题；知识丰富 / 知识贫乏问题 | 区分“资料齐全的病例”与“只有主诉、需要先补信息的病例”，决定策略而不是同一套流程 | 对应 `md/14` 的“缺失必须显式记录” |
| 问题表征质量决定求解质量 | 把“病例结构化程度”作为策略输入，而不是假定输入总是合格 | 与 CanonicalCase 前置一致 |
| 组块（chunk）与图式（schema） | 解释为什么专家用少数高层结构快速定位，而新手逐条匹配 | 支持“先骨架后细节”的两段式检索 |
| 专家“顺向法”（整体→局部）/ 新手“逆向法”（目标→反推） | 对应 `md/07` 的“已验证路径复用 + 即时知识推演”两种模式 | 可作策略参数，不宜直接当医家 profile |
| 概念对 CP（偏序：抽象→具体） | 最小思维单元可以是“两个概念 + 有向关系”，而不是自由文本 | 与 `LocalGraphEdge` 的 source/target/relation 同形 |
| 概念层次权重 `chw = h1 − hi + 1` | 给“先看哪一层”一个可解释排序量 | 只是排序量，不是重要度概率 |
| 思维序列 TS（路径唯一性 + 层次序） | 一条候选推理路径 = 有向序列，可记录、可比较、可回放 | 与证明路径/决策摘要一致 |
| 分析问题 AQ（频次集、特征、特征向量） | 把“多条路径”聚成“问题族”，再做主题 | 相似度只是结构相似，不是医学相似 |
| 特征 = 区分度 × 层次权重 | 区分度 `log(N/频次)` 可作“特异性”的近似 | 不可表述为临床概率 |
| AQ 的可加性与增量更新 | 新病例/新路径可并入已有问题并更新特征 | 对应包版本化增量，但不改写进行中的病例 |
| 层次聚类得主题 TKT | 主题 = 问题族的上层归纳，可解释“为什么这些路径属于一类” | 聚类结果需人工命名与复核 |

### 3.2 关键形式化（仅作结构参考，不作为本项目公式）

书中的表达链为：

```text
概念对 CP <ci, cj>（ci 偏序高于 cj）
  → 概念集 CS → 邻接/可达矩阵 → 概念层次 H → 位序表 BOT → 层次权重 chw
  → 思维序列 TS（由 CP 拼接，前一条的后继 = 后一条的前驱）
  → 分析问题 AQ = <AQTS, AQCS, AQF, AQFV>
  → 分析主题 TKT = {AQ}（余弦相似度 + 层次聚类）
```

其中 `AQF` 取频次 ≥ α 的概念，`feature = log(N/AQCS) × chw` 并归一化。示例参数 α=0.6、β=0.5、η=0.3（第 63、75 页），属人工拍定，未做敏感性分析。

## 4. 候选骨架（草案，非最终设计）

以下只是“如果要实现，形状可能是什么”，用于讨论取舍；不构成设计确认。

### 4.1 分层

```text
数据接口（只读）
  → 病例状态与观察（CanonicalCase）
  → 局部知识子图（LocalKnowledgeGraph，按分类/字段/节点过滤）
  → 概念轴索引（包外，由注册表 + 分类 + 来源统计生成）
  → 规则单元投影（包外，RuleUnit）
  → 候选图（假设 / 机制 / 状态 / 冲突 / 缺失）
  → 追问选择
  → 停止决策
  → 输出 + 运行痕迹（包外，含版本）
```

### 4.2 RuleUnit 候选字段

| 字段 | 含义 | 来源约束 |
|---|---|---|
| `conditions` | 适用前提与症状组合 | 必须逐条绑定原文/证据 |
| `decision` | 判断或结论（证候、病机、选方） | 标注原文陈述 / 规则推出 / 模型候选 |
| `exclusions` | 排除或禁止态 | 与 `conditions` 同级，不得被覆盖 |
| `adjustments` | 加 / 减 / 换 / 停，四类分开 | 每类含触发条件与动作，保留变更前后值 |
| `limits` | 适用限制、禁忌、慎用 | 与“无效”“不适用”区分 |
| `scope` | 医家 / 篇章 / 文本类型（证治条文、方论、医案） | 来自来源身份，不跨篇合并 |
| `relations` | 并列 / 承接 / 总分 / 互斥 / 递进 | 需版本化词表；承接关系必须保留前文引用 |
| `provenance` | 原文、出处、定位、审核状态、生成方式 | 归纳与原文分离 |

三条硬规则：条件必须绑定；`若…者` 不得脱离前文；互斥分支必须显式标注。目的是防住“见发热汗出即用桂枝汤”这类全局化跃迁。

### 4.3 概念轴（多轴，不合并）

书中只有一条偏序（抽象→具体）与一张位序表。中医至少需要四条轴：抽象—具体、整体—部分、因果/传变、治则—治法—方药层级。建议：

- 每条轴独立建偏序，不跨轴推传递性；同一概念可同时位于多条轴的不同层级。
- 共现关系与层次关系**分开建图**。中医概念常互为因果，混在一张图里会产生环，书的“可达矩阵逐层剥离”会直接失败。
- 权重只用于“先展开哪一层”的排序，并标注推导版本、来源范围与统计口径。
- 不把“层次高”解释为“更重要”或“更可能”。

### 4.4 路径：模板 + 有界扩展

书中的做法是对概念对集合枚举所有“入度出度均为 0”的思维序列（示例 16 个概念得 63 条；8 个数据集最大 80 万条，序列构建约 10,432 秒，第 53、79 页）。中医图更大且多义，枚举不可行。候选替代：

- 以 `md/14` 的临床认知链为模板，从病例观察出发做有界扩展（每轮只展开最能区分当前候选的邻居）。
- 设每轮节点预算与调用预算，记录剪枝依据与放弃分支。
- 把“完整性/完备性”降级为**覆盖度与边际收益**：不要求每条路径首尾贯通，要求“关键环节缺失可见”。

### 4.5 评分与追问（示意，非公式定稿）

- 候选支持分：证据权重 × 条件匹配度，减去反证惩罚与缺失惩罚；权重按来源强度、审核状态、医家作用域、时间窗分层。
- 追问选择：候选间期望区分度 × 可获取性/安全成本；能解释“为什么问这个”。
- 缺失三分：未问 / 问而不知 / 明确阴性（注册表已有“未提及不等于不存在”的口径）。
- 一切分值标注产生方法与版本；不得表述为临床概率。

### 4.6 停止决策

三类出口：收敛（前两候选间隔足够）、边际（新增观测的信息增益低于阈值）、外部触发（安全门、必须转诊、资源耗尽）。停止不等于确诊；输出恒为多候选 + 支持/反证/缺失 + 不确定性 + 安全状态。方剂、剂量、停调无来源证据时输出“需复核”，不补全。

### 4.7 留痕与记忆

- 每轮记录：包版本、召回范围、命中/未命中、候选变化、剪枝依据、放弃分支、阈值集、规则与提示版本。
- 记忆分层沿用 `md/07`（会话工作记忆 / 阶段摘要 / 长期偏好 / 临床资料独立域），不新增层级。
- 运行痕迹与索引放包外，不改写原始事实与来源身份，不写回数据包。

### 4.8 若确认，需要修订的既有文档

`md/07`（§2 两种模式、§3 专家思维模拟、§4 病例讨论流程）、`md/14`（§3 认知链、§5 证据化多路径）、`md/03`（§2 图/树/链、§4 跨层关系词表）。这是设计动作，不是本次改动。

| 停服与停调条件 | `tcm.safety_stop_conditions`、`formula.stop_rule` |

语义注册表现状（实测）：`medicine-agent.semantic-registry` v0.3.2，status `review`，197 个字段、10 个关系、5 个 profile、64 条 schema binding。字段足以承载条件、加减、停服、禁忌与配伍，**样例不需要新增字段或改包**。

### 5.2 实测缺口（附录 B 有复现方式）

1. **字段覆盖面**：真实包 478 个字段全部属于 `tcm_foundation`（`groups.kind` 只有 `theory`），没有一个 `tcm_formula_*`、`tcm_differentiation_*`、`tcm_safety_*` 字段。B20 正在补五类最小闭环，但每类 1 字段，尚不构成思维层可用规模。
2. **关系为空**：该包 `relations.jsonl` 为 0 条。图遍历目前只能靠分类/字段过滤，`md/03` 设计的关系词表尚未落地。
3. **粒度**：一条节点 = 一个段落级命题（statement 40–75 字），不是“条文 + 条件组 + 分支”。样例的 U03 两支在现有粒度下只能压进一个 statement 自由文本，无法被机器区分。是否改为“一条条文一个 node / 一个条件组一个 group”，属数据生产决策，需单独确认。
4. **关系词表偏窄**：包内知识链接 Schema 只有 4 种（same_definition / related / expands / contradicts），语义注册表 10 种，缺“条件分支 / 加减触发 / 停服 / 互斥 / 承接 / 总分 / 适用限制 vs 禁忌”。`LocalGraphEdge.relation` 是自由字符串，可先在包外定义词表并版本化，不必改 Schema。
5. **思维层对象全缺**：查询计划、候选集、追问选择、停止决策、运行痕迹都没有对应实现。现有 `tcm_reasoning` 是 5 组关键词硬编码的脚手架（自身声明 unreviewed candidate），只能当接口样例。
6. **设计—实现不一致**：`md/03` §4 列出的“细化 / 组合 / 采用 / 偏离”等关系，注册表里没有，需要一并校正口径（属数据层文档一致性，不是思维层实现）。

## 6. 不可照搬清单

1. **单一层次 + 唯一位序表**：书假定概念层次唯一、顺序唯一；中医多轴、多学派、条件分支会直接破坏该假设。
2. **全路径枚举**：规模上不可行；且“入度出度均为 0 的最终思维序列”在临床上没有对应物。
3. **余弦相似度 = 主题相似**：它衡量的是概念共现的结构相似，不是医学相似，不能当证候合并依据。
4. **阈值拍定**：α/β/η 与 `log(N/频次)` 的底数、样本口径都需重新定义，且必须做敏感性分析；不能把参数当医学判据。
5. **“专家 = 顺向法”的普适性**：书中的专家/新手结论来自访谈与特定领域（商品、网络数据），中医各科差异大，需要真实材料验证。
6. **工程与性能结论**：Java/WinXP 时代的耗时与外推不能用于当前容量规划。
7. **CRISP-DM 类比**：书把“分析主题发现”映射到数据挖掘业务理解；本项目是临床辅助，目标与风险结构不同，不能直接套用其任务定义。

## 8. 开放问题（需用户决定）

1. **首个可验收目标**：先做“文献 → 条件单元索引”（数据侧、可立即推进），还是先做“病例 → 多候选 + 追问 + 停止”的最小闭环（跨入思维层确认门）？建议先做前者，它同时是后者的前置。
2. **策略口径**：首版是通用病机骨架，还是按医家 profile 分叉？按书中的专家差异推断，profile 只能来自真实材料与人工确认，不能凭常识生成。
3. **包外存储边界**：思维索引、运行痕迹、验收集放包外的哪个位置（独立索引目录 / `artifacts/` 临时产物 / 新目录），需要明确，避免被当成包结构的一部分。
4. **数据粒度**：是否把生产粒度改为“一条条文一个 node、一个条件组一个 group”？这是数据层决策，影响 B20 之后的产包口径与旧包兼容。
5. **分值展示口径**：是否允许向用户展示候选排序分，以及如何标注“非概率、非诊断”。
