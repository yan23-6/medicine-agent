# 统一医学语义说明书

本目录是项目字段、关系、术语体系引用和专业分流规则的唯一规范位置。

## 唯一来源

- `registry.json`：唯一机器可读语义注册表，保存字段定义、值类型、关系、外部术语体系元数据、权威来源、Profile 路由和物理 Schema 绑定；
- `registry.py`：只负责读取与校验注册表结构，不重新定义医学字段；
- 本文件：只解释使用方法，不复制 `registry.json` 中的字段清单。

其他 `md`、任务文档、Skill 说明、Schema 和数据包只能引用注册表中的 `field_id`、`relation_id`、Profile 和版本，不能建立第二份同功能字段字典。具体数据包只声明采用的注册表版本与 Profile，不得改变公共字段含义。

## 分流规则

1. 所有对象先使用 `common`：身份、来源、原始值、规范值、时间、诊次、证据、血缘、审核和适用范围都属于通用层。
2. 中医内容增加 `tcm`，西医内容增加 `western`；同一病例可同时启用，但两个 Profile 不互相改写专业概念。
3. 安全评估增加 `safety`，其阻断与限制优先于中医、西医和方剂路径。
4. 方剂增加 `formula`，并继承通用、中医和安全约束；药物固有知识与方中角色分开。
5. 不确定属于哪个专业时保留在通用原始层并标记未映射，不凭关键词强制分流。

## AI 与 Skill 使用要求

每次需要解释或生成医学结构的 AI/Skill 必须读取或由运行时注入：

- 语义注册表版本；
- 本次启用的 Profile；
- 允许使用的术语体系及版本；
- 未映射、歧义、缺失和审核策略。

AI 可以提出映射候选，不能自造外部代码、覆盖原文或把模型候选标为人工确认。若输出使用未知字段、跨 Profile 字段或重复定义通用语义，校验应失败并进入人工复核。

## 维护流程

普通医学内容更新进入知识包，不修改本说明书。只有现有字段、关系或 Profile 无法表达新的真实语义时才修改 `registry.json`，同时升级版本、说明迁移影响并运行：

```powershell
uv run medicine-agent validate-semantics
uv run pytest
```

外部标准目前只登记元数据和引用状态，没有把受许可约束的完整术语内容复制进仓库。实际导入前必须重新确认版本、许可和映射范围。
