# 独立智能体：文件分析、断点续跑与可迁移数据包

> 本文件沿用原 PDF 文件名以保持已有链接；设计范围是产品自身的多格式资料能力。
> 本章定义稳定能力和边界；当前实现与真实验收状态只看 `tasks/STATE.md`。

## 1. 整体产品，而非开发环境代劳

交付的是可在其他电脑独立安装运行的医学智能体。Codex 只用于开发，最终用户不需要 Codex、当前聊天、开发者账号或本仓库工作目录。文件识别、OCR、内容分析、暂停继续、包管理和知识查询都必须存在于产品运行时及其发行依赖中。必要的模型服务由运行产品的用户自行配置，不继承开发会话登录；独立运行不自动等于所有模型均可离线运行。

整体有两条主线：

1. 资料学习：接收文件 → 识别格式与内容 → 提取/OCR → 分析知识与病例 → 校验 → 生成或更新数据包；可暂停、重启和继续。
2. 问诊辅助：读取已启用的数据包 → 收集病例信息并追问 → 检索证据 → 当前中医候选分析与安全检查（西医仅未来接口）→ 返回出处、缺失和不确定项。

两条主线共享同一字段说明书、来源证据、包版本和病例事实。知识包里的医学内容、产品里可执行的能力、模型配置分别管理；复制知识包不应替换程序或模型。问诊遵守既有产品边界，内容检索通过不等于问诊功能已经验收。尚未确定的其他功能只保留扩展入口，不编造需求。

## 2. 总智能体与小智能体

用户明确的产品角色名称统一为“数据分析 Agent”，承接下文资料处理小智能体及原 KnowledgeBuilderAgent 的职责，不额外增加一个重复角色。用户调用的是数据分析 Agent 的文件到包完整能力；知识蒸馏 Skill 保留为其调用的内部分析工具，OCR、任务恢复、包构建和查询分别由受控工具提供。对外输入为文件、处理要求和目标包，输出为可恢复任务、可迁移包与检查结果；验收覆盖整条流程，不能仅凭单个 Skill 成功认定完成。实现时同步登记名称和兼容说明，不把本次设计更名当作 Agent 已存在。

用户把文件交给总智能体，总智能体建立可持久化任务，交给资料处理小智能体。后者通过注册工具完成识别、提取、OCR、分析与构建，再由确定性检查及必要人工复核控制可用状态。对应既有 OrchestratorAgent 与 KnowledgeBuilderAgent，不为每个格式另造顶层 Agent。

暂停、恢复、文件身份、进度、写入与版本切换由程序保障，不依赖模型记忆“做到哪了”。工具先真实实现并验收，Agent 再调用。CLI、未来 Web/MCP/REST 和外部宿主共用相同核心接口。

## 3. 多格式接收与扩展

产品必须提供能力清单，区分已经可用、缺少依赖、尚不支持；识别实际文件内容，扩展名和实际格式冲突须报告，不能任意执行文件。

首批格式范围为 PDF（文本、扫描、混合）、DOCX、TXT、Markdown、PNG/JPEG。后续电子表格、HTML、EPUB 等通过适配器扩展，未验收前不得声称“任何格式都能读”。DOCX 依据文档结构定位，不能伪造固定页码；图片依据像素区域，文本依据行/段。

材料类型还需按片段判断：教材、论文、医家经验、病例、表格或混合内容；不能把一整本书或所有文件都套成同一个模板。

OCR 后端可替换；首选可随产品部署的本地中文识字方式，实际依赖和许可在实现时验证。现有文本模型没有视觉能力，不得当作 OCR。远程识字需显式配置服务和传输范围；发行时提供所需模型资源或受控的一次性准备方式，不能只在开发机器缓存里可用。

本地OCR应在执行前核对已验收后端版本、默认配置与所需模型文件的大小和内容哈希。缺失、变更或未评估时明确阻断，不在文件处理途中隐式联网下载。能力清单区分支持格式、依赖元数据、本地资源就绪和实际原生运行；本地资源通过不等于OCR准确率、医学正确性或资源再分发许可。资源描述与识字模型留在运行发行层，不进入医学知识包。

## 4. 原文、识别结果和出处

每条知识或关系引用一条或多条实际证据，并能回到来源文件及精确位置。PDF 记录从 1 开始的物理页码、页面大小和文字块区域；坐标保留单位、原点、旋转与缩放关系。印刷页码另存且允许未知。

原始提取/OCR 输出不可覆盖；纠正候选、依据、模型解释与人工确认分别保存。表格、图片、阅读顺序或字迹无法可靠恢复时保留区域与缺口，不能悄悄略过。模型不得编造证据引用、外部代码、作者、版次或医学结论。

字段和关系继续以 `src/medicine_agent/semantics/registry.json` 为唯一机器可读说明书。新增真实语义先登记并升级契约，再更新模型和快照；本章不另造字段字典。

## 5. 一本书处理到第 100 页后继续

以 200 页为例：程序持久化每页每阶段的输入身份、状态、输出位置和校验信息。OCR 完成不等于该页知识分析完成；进度必须能反映两者差异，不能只保存一个页码整数。

- 用户暂停后停止派发新单元，在可提交边界保存已完成结果，明确当前调用的处理状态；已经提交的单元不重复处理。
- 关闭程序或意外退出后，新进程从磁盘恢复。若第 100 页完整提交，从 101 页继续；若第 100 页做到一半，从该页最早未完成的阶段继续。
- 恢复时校验文件内容指纹、选择范围、协议、工具和分析配置。路径改变可按相同指纹重新绑定；文件内容或关键配置改变须明确失效范围或另建任务，不静默混用旧结果。
- 输出先落盘并校验再提交状态；损坏缓存、未提交文件、遗留运行标记可检测并恢复。中途失败可以重算一个未提交调用，不承诺外部模型计费的恰好一次。
- 阶段性成果显示处理范围；未完成任务不是完整新包。可显式导出已完成范围的部分候选包，清楚标明缺页，原有可用包保持不变。
- 跨页分析保留必要上下文和章节边界，恢复后不丢跨页关系、不重复计入重叠片段；最终重新校验引用和覆盖范围。

所有格式按稳定页/段/块划分可恢复单元。单本长书的暂停恢复属于当前交付；多文件大规模调度可后续扩展。

## 6. 数据包放一个文件夹，复制到另一台电脑使用

最终产品从固定的 `<用户目录>/MedicineAgent/knowledge/` 目录发现数据包文件（`.medpkg`）和平台统一说明书。产品在启动或显式刷新时自动发现、校验并列出状态；兼容且满足使用范围的版本自动进入相应查询范围，损坏或不兼容包报告原因。首次索引可以耗时，但无需修改提示词、手写注册表或逐包写说明书。

最终完成包是一个文件，自包含知识、关系、必要证据文本、来源位置、协议与包版本、处理范围、审核状态和完整性信息。内部资源使用包内相对引用，不依赖开发机绝对路径、聊天附件地址、临时目录或当前数据库文件。大型原件可按许可选择附带；不附带时仍可查证据文本和出处，但明确无法视觉核对原页。

只复制完成的数据包文件到另一台已安装兼容产品的电脑固定发现目录，即可重新发现、校验并查询；不需要原始文件、原任务记录、开发仓库或 Codex。索引是可重建缓存。新电脑如需模型分析或对话，配置自己的模型；已有包的基本结构化查询与证据读取不能因缺少生成模型而不可用。

任务工作区、内部解包和索引缓存与最终包文件分开。只迁移完成结果不要求携带任务缓存；迁移未完成任务则需要输入资料、检查点及所引用中间产物，重新绑定路径并验证版本。这两种迁移不能混为一谈。

## 7. 更新、查询和问诊之间的衔接

数据包按第 04 章独立保存科目/专题、资料类型、专业 Profile 和适用的中医三层归属，以及分类依据和候选/声明状态。用户可提供分类；程序与模型的推断保持候选，未知显式未分类。分类必须随包迁移，目录查询支持相应过滤，旧包与新修订不能丢失或猜测分类。文件格式不能代替内容分类。

新增独立来源默认生成独立包；同一来源的补充页或重分析生成新修订，记录父修订、输入指纹和差异，旧版保留。相同任务重试不无控制地产生重复节点或覆盖结果。新修订先完成校验、查询及来源回溯，再切换选用版本；失败保持旧版可用。

实验阶段必须提供包目录发现、版本选择、跨已启用包的基本查询和证据回溯，证明产物能被整体智能体消费；不以未来数据库尚未接入为由跳过文件迁移验收。正式存储阶段再冻结协议、接入 LadybugDB 与完整索引，不重新定义来源语义。

问诊功能后续复用同一包目录和查询接口，固定本次会话使用的包版本，更新包不偷偷改写进行中的病例结论。研究候选、已审核知识及隔离内容有明确使用范围；放进文件夹不等于自动获得医学审核。未实现安全与专业能力时明确返回能力缺失，不用普通聊天伪装完成问诊。

## 8. 建设顺序与验收要求

先验收独立产品中的多格式分析、持久化暂停恢复、实验包修订、固定目录发现与迁移，再进入真实教材和人工核对；正式包与数据库随后冻结，问诊辅助与完整角色协作最后接入同一任务和包能力。自制材料可验证软件行为，但不能替代真实 OCR、真实模型和医学审核。

验收必须包括真实 OCR、真实模型短样例、进程退出恢复、200 页任务在第 100 页中断、迁移完成包到隔离目录，以及仅安装发行物且无 Codex/源码路径的独立运行。模拟测试不能代替真实识字；独立目录测试不能夸称已验证所有操作系统或实际第二台电脑。

## 9. 用户原始 PDF 与代码仓库分离

`pdfs/` 是本地原始资料入口。具体任务在获得相应授权后可读取、OCR、分析并制作必要的本地快照，但禁止将其中 PDF 原件提交到 Git。Git 仅保留 `.gitkeep` 文件夹占位；`.gitignore` 忽略其他全部内容，包括后续新增或改名文件。不得强制添加，也不得复制到其他受跟踪目录以绕过限制。

源 PDF 不放入测试夹具、发行物或文档附件。生成的 OCR、页面预览、检查点、原件快照、模型候选与实验包放到被忽略的 `artifacts/`；稳定设计和不含整页正文的验收摘要可继续保存在 md/tasks。分析前后核对原件指纹，不修改原书。原件不提交不影响包内保留必要引文与出处，但候选包不因此获得公开分发许可。


## 10. 候选修订

候选更正由总智能体的 `revise_candidate` 入口复用数据分析侧包目录服务；不新增 Skill 或第二个分析 Agent。输入为父包路径与明确复核 ID，输出独立候选包及修改历史。精确断点缓存只复用已提交处理，新资料中的同名概念仍须保存新原文。


## 11. 用户归属与联合使用边界

任何用户可基于多人的成品包继续学习新资料。来源/制作者不是更新权限；新资料完整读取原文，派生包继承基础包未涉及的内容，并保留所有来源。精确缓存只按文件指纹、配置和上下文判断有效性。


## 12. 原文优先与引用边界

最大限度保留原文：实际材料来源与其转引文献/观点归属分开；原话字段逐字校验，独立命题分别组织；当前页、上下文、版面文字和已在别处引用的提示明确区分。完整 OCR、引用、位置、旧节点和历史提示不删除；新语义、工具和策略必须版本化。正式存储继续使用唯一语义注册表，不重建另一套医学字典。

## 13. 已处理范围与后补数据包

覆盖盘点是独立版本化的只读管理能力，不是新 Agent 或 Skill。其结构源为 `domain/coverage.py`，契约快照在 `schemas/coverage/`；提取和中医语义候选分别记录，软件覆盖不代表医学审核。历史声明、停用版本、未知字段与策略不兼容分别处理；不明来源不能仅按书名绑定，缺包不等于从未处理。输出仅为最早缺失阶段的建议，绝不自动派发。完整性或身份失败隔离整个文件，其他文件继续；单位混淆、越界和修订冲突待核，不静默截断合并。源目录只读，解包缓存必须在目录之外。

资料不足时优先使用用户已提供且许可适用的本地原件，不因旧包尚未拷入而停止不依赖旧包的工程建设。每次先按原件SHA256、从1开始的物理页码、处理阶段、策略版本和包完整性核对覆盖范围；新任务排除已有有效OCR或语义成果的相应阶段，只补最早缺失阶段，不能把“未发现包”直接当成“从未处理”。

历史报告有覆盖记录而包待补时，将范围标为待核/暂避，不自动重蒸馏。后补包先校验身份、版本、来源、页范围和哈希，重新核对覆盖台账；与现有包并存，冲突走明确版本选择，不覆盖或按同名概念自动合并。页范围去重只用于同一来源的重复工作控制，不阻止不同来源对同一概念分别保留证据。

知识包蒸馏、训练候选数据准备和模型权重后训练分别管理。仅在当前任务确有数据缺口时选择最小新增范围，不以建设框架为由整书重蒸馏；未来训练/验证/测试按来源和相邻内容分组隔离，不能仅按页随机切分造成泄漏。处理许可不自动等于公开再分发或权重训练许可；外发仍需匹配明确资料范围与配置服务。
