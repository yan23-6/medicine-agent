# 接口与扩展约定

## 1. 稳定公共能力

平台首先固定能力语义，再决定具体协议字段。核心公共能力包括：

- 列出可用知识包及其状态；
- 查询平台支持的统一知识包协议版本和资料类型配置；
- 安装、校验、启用、停用、升级和卸载知识包；
- 查询病机概念、关系和来源；
- 获取三层病机树；
- 获取某位医家的病机经验；
- 获取医案及诊次病机链；
- 比较多位医家的推理路径；
- 根据病例证据生成候选病机；
- 获取支持、反证、缺失信息和引用；
- 提交人工评审；
- 查询版本、错误和质量报告。
- 获取组合式 FormulaSkill 的八类内部能力及统一药物层结果；
- 在后训练阶段启用后，查询模型注册表、训练数据快照、适用任务、评测状态和当前灰度版本；

## 2. 智能体接入能力边界

智能体接入至少覆盖知识包发现、病机检索、三层结构查看、医家经验查询、医案路径查询、多医家比较、病例证据分析、来源回溯和质量状态查询。具体工具名称、参数和返回 Schema 留到接口设计阶段确定。

对外能力的语义需要稳定，内部模型和 LadybugDB 查询方式可以替换。高权限写入能力默认不向公众或普通智能体开放。

## 3. REST API 与 SDK

REST API、MCP 和其他环境适配方式必须使用相同的平台能力和评分结果，不能各自实现一套病机逻辑。具体 SDK、协议字段和技术栈留到后续设计。

## 4. 返回结果要求

医学查询结果至少包含：

- 结果类型和稳定标识；
- 内容与规范术语；
- 来源和原文位置；
- 原文、整理、模型候选或专家确认状态；
- 适用条件和作用域；
- 支持证据、反证和缺失项；
- 置信或支持维度；
- 包版本、算法版本和审核状态；
- 医疗安全提示级别。
- 实际使用的基础或后训练模型版本、知识包集合、检索配置和 FormulaSkill 版本。

接口不能只返回一段无法追溯的自然语言。

## 5. 兼容与版本

- 项目只维护一套统一知识包协议说明书，知识包 Schema 使用语义化版本；
- 每个数据包声明其协议版本和最小机器自描述，但不定义独立使用说明；
- API 和 MCP 工具声明版本；
- 新增可选字段保持向后兼容；
- 删除或改变字段语义必须提升主版本；
- 适配包声明支持的核心平台和知识包版本范围；
- 核心平台升级前运行旧包兼容性测试；
- 不兼容包进入隔离区，并给出迁移报告。
- 后训练模型与知识包独立版本化；具体模型能力版本和兼容要求由未来实施方案根据已经稳定的接口确定，不能把模型升级伪装成知识包升级。

## 6. 错误语义

统一区分：输入不完整、权限不足、包不可用、版本不兼容、证据不足、未找到、存在冲突、需要专家复核、医疗安全阻断和内部失败。智能体不能把“证据不足”改写成否定结论，也不能把“需要复核”显示成已确认。

## 7. 扩展原则

新增普通科室、医家、材料或智能体环境时，优先增加统一结构的数据包、资料类型配置或适配器，不修改核心医学事实，也不新增包级说明书。只有现有 Schema 无法表达新的真实关系时才扩展唯一核心规范，并同步升级项目级说明书、迁移规则和回归测试。

默认存储实现为内嵌 LadybugDB。若未来增加服务器型存储，只能作为可选部署能力，并保持知识包语义、联合查询结果和来源边界一致；不得使普通安装被迫增加外部数据库依赖。

新增方剂时优先增加兼容知识对象和组合式 FormulaSkill 数据，不为每味药新增顶层 Skill。新增单味药知识应进入可复用 HerbKnowledge；只有药物在某一方中的具体角色、剂量、炮制、配伍和条件规则进入该方剂的 DrugLayerSkill。
