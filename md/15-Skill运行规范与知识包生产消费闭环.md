# Skill 运行规范与知识包生产消费闭环

本文定义 Skill 从设计概念变成真实可调用能力所需的最低契约，并固定正式蒸馏开始前必须完成的生产—校验—消费闭环。

## 1. 当前事实

当前仓库只有需求、设计和导师参考材料，尚不存在可执行 Skill、Agent、Schema、知识包工具、数据库导入器或服务。设计文档中的能力名称均为目标，不得解释为已经实现。

## 2. Skill 的成立条件

Skill 不是单独一份提示词或 `SKILL.md`。一个 Skill 只有同时具备以下部分并通过验收，才算可调用：

1. 稳定身份、名称、版本和适用任务；
2. 机器可校验的输入与输出 Schema；
3. 可执行调用入口；
4. 实现代码、确定性规则、模型调用或受控工具；
5. 证据、来源、权限和安全约束；
6. 标准错误码、失败语义、重试与幂等要求；
7. 调用日志、依赖版本和可复现信息；
8. 测试夹具、金标准或契约样本；
9. 自动测试与验收报告；
10. 变更记录和兼容范围。

Skill 的自然语言说明帮助 Agent 正确调用，但不能替代实现和测试。

## 3. Skill 分层

平台基线使用十一类核心 Skill 家族：材料摄取、证据定位、知识蒸馏、病例蒸馏、中医推理、西医推理、安全门、方剂、知识包构建校验、知识包查询和质量评价。详细职责以 `tasks/overall/终极需求.md` 为准。

顶层 Skill 保持面向完整任务，内部能力不全部发布成独立 Skill。例如 KnowledgeDistillationSkill 可以内部调用分段、实体抽取、关系抽取和术语规范化函数；FormulaSkill 内部包含统一药物层，不为每味药发布顶层 Skill。

通用与专业能力采用组合关系：

```text
通用材料与证据能力 + 中医专业扩展 = 中医知识或病例蒸馏
通用材料与证据能力 + 西医专业扩展 = 西医知识或病例蒸馏
```

## 4. 统一调用契约

每次 Skill 调用至少记录：

- task_id、skill_id 和 skill_version；
- 输入对象身份及其版本或指纹；
- 调用者 Agent 或人工主体；
- 模型、规则、提示和工具版本；
- 输出对象及其 Schema 版本；
- 证据引用、生成方式和审核状态；
- 警告、错误、缺失项和安全状态；
- 开始、结束、耗时和资源信息。

Skill 默认输出候选对象，不能直接写入正式知识库。候选结果经 Schema 校验、质量门和必要人工审核后，由版本化发布服务写入正式数据。

Skill 不能为了满足规范 Schema 而丢弃不明确输入。原始字段先完整保存；不同 key 同义、同 key 异义、重复出现或无法映射时，分别记录原始观察、规范候选、映射依据、冲突和审核状态。统一字段语义由项目级知识包说明书解释，单个 Skill 或数据包不能私自改变。

## 5. 一致性和可用性保证

数据一致性由统一 Schema、稳定身份、证据引用、Skill 版本、确定性校验、质量门和回归测试保证，不由 Agent 自由文本保证。

知识包可用性必须由消费端验证。任何知识包生产能力都必须同时具备：

- Build：从已校验对象封装知识包；
- Validate：检查协议、身份、证据、版本、完整性和许可；
- Query：读取或安装后完成规定查询；
- Trace：从查询结果回到来源证据；
- Round-trip：导出后重新读取，语义和身份不丢失。

只完成 Build 而没有 Validate 和 Query，不得声称知识包已经可用。

## 6. 最小生产消费闭环

正式蒸馏开始前必须跑通：

```text
测试材料
  → MaterialIngestionSkill
  → EvidenceGroundingSkill
  → 最小知识对象
  → KnowledgePackageBuildValidateSkill
  → 实验知识包
  → KnowledgePackageQuerySkill
  → 知识 关系 来源证据
  → 自动契约与往返测试
```

这个闭环首先验证 Skill 协议、Schema、包结构和查询兼容性，不要求第一次就完成全部中医或西医语义。闭环通过后，再增加 TCMReasoningSkill、CaseDistillationSkill 等专业能力。

## 7. 正式蒸馏启动门

只有以下条件满足，才允许开始一本书或一批医案的正式蒸馏：

- 所需生产 Skill 已实现并登记；
- 输入输出 Schema 已版本化；
- Build、Validate、Query 和 Trace 通过；
- 至少一批测试样本和预期结果存在；
- 错误、断点和重跑机制可用；
- 原文、模型候选和专家确认可以区分；
- 质量门和人工复核路径明确；
- 包格式或实验格式能够被消费端读取；
- 许可、隐私和安全条件允许。

使用真实 LLM 时还必须通过统一模型适配层读取本地或部署环境配置。密钥不得进入 Git、日志、知识包、运行记录或测试快照；模型输出仍需经过 Schema、证据和质量检查。

测试材料可以在此之前用于开发和验收，但不得把开发输出标记为正式知识包。

## 8. Agent 启用门

Skill 尚未稳定时使用确定性工作流和直接调用。最小生产消费闭环稳定后，才启用三个初始逻辑 Agent：编排、知识构建和证据评审。中医、西医与安全治理 Agent 在对应专业 Skill 和安全 Skill 通过验收后启用。

Agent 只能从 Skill 注册表选择已实现且兼容的 Skill。找不到能力时必须返回“能力不存在或版本不兼容”，不得通过自由生成假装调用成功。

## 9. 物理格式与实现空间

当前固定 Skill 和知识包的语义要求，不提前锁定全部目录、字段和运行框架。T01 选择最小实现技术并形成可迁移参考实现；阶段 03 根据真实输出冻结知识包 v0 物理格式和 LadybugDB 映射。实现变化不得破坏来源、证据、身份、版本、专业体系和审核状态。
