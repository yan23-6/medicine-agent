# 中西医临床认知与多智能体架构

本文定义平台最高层的业务与执行架构。平台以通用医学知识和临床认知过程为主干，在同一证据、病例、时间、治理和安全框架下分出中医与西医专业路径。Agent 负责协作和决策，Skill 负责可复用的具体能力，统一知识包与病例数据模型负责保存可追溯事实和过程状态。

## 1. 最高级架构原则

```text
Agent 负责协作和决策
  ↓ 调用
Skill 负责具体能力
  ↓ 受控读写
统一知识包与病例数据模型
```

这三个层级不能混为一体：

- Agent 是有职责、状态、权限和输入输出约束的执行角色，负责拆分任务、选择路径、调用 Skill、处理失败和汇总结果；
- Skill 是可版本化、可测试、可组合的能力单元，负责标准化、抽取、检索、推理、评审或安全检查，不自行拥有正式医学事实；
- 统一知识包与病例数据模型保存证据、知识、病例状态、过程结果、版本和审核信息，Agent 与 Skill 均通过平台接口访问，不能直接任意修改正式库。

一个 Agent 可以调用多个 Skill，同一个 Skill 也可以被多个 Agent 复用。Agent、Skill、模型和进程不要求一一对应；同一模型可承担多个受控角色，关键是职责、权限、状态和评价可分离。

导师提出的数十个智能体是平台成熟后的可扩展方向，不是初始实现要求。Skill 和确定性工作流稳定后，MVP 先启用编排、知识构建和证据评审三个逻辑角色，再依据对应 Skill、任务负载、错误归因、权限隔离和独立评价需要启用中医、西医与安全治理角色，禁止仅为增加数量制造无效 Agent 对话。

## 2. 通用主干与专业分支

平台不是两个互不相干的中医、西医系统，也不把两套理论强行融合。统一主干处理两者共有的材料、病例和治理问题，专业分支承载各自不可替代的方法、概念和知识。

```text
通用医学主干
原始材料或病例
  → 来源登记与证据保真
  → 标准化观察与时间线
  → 多假设生成
  → 专业机制解释
  → 支持 反证 缺失与冲突
  → 综合状态
  → 目标与干预
  → 状态变化与结果

  ├─ 中医分支
  │  四诊 病因 病位 病性 病机 证候 治法 方剂 药物 针灸 传变
  │
  └─ 西医分支
     病史 体征 检查 危险因素 病理生理 诊断 鉴别 风险 干预 预后
```

两条分支共享患者、诊次、时间、原始观察、来源证据、干预、结局、安全门和审核状态。中医病机与西医病理生理分别建模，只能在有依据时建立“相关、互补或共同指向某观察”的映射，不能把二者声明为天然等价。

当前数据和论文验证以中医为主，中医病机三层结构是首个专业深化方案；西医分支先通过小型样本验证统一主干没有被写死为中医专用结构。

## 3. 通用临床认知链

平台统一采用可审计的临床认知对象，而不是保存模型不可见、不可复核的隐藏思维过程。完整逻辑链为：

```text
Observation  原始观察
  → Feature  标准化特征
  → Hypothesis  多个候选假设
  → Mechanism  中医病机或西医病理生理机制
  → Conflict  冲突 矛盾 反证与缺失信息
  → State  当前综合状态
  → Goal  治疗或处置目标
  → Operator  实现目标的抽象操作
  → Action  实际或候选干预
  → Transition  状态变化
  → Response  随访观察与结局
```

该链是统一逻辑契约，不要求每份材料都包含全部环节。缺失环节必须显式记录，不能由模型静默补齐。系统展示的是有证据、有来源、有审核状态的推理图、证明路径或决策摘要，不要求模型输出私有思维链。

## 4. 原始医案与标准病例

每份医案先经过 `RawCase → CanonicalCase`，再进入中西医推演。标准化过程至少包括：

- 患者与就诊身份的去标识化信息；
- 主诉、现病史、既往史、治疗史和时间变化；
- 症状、体征、检查、舌象、脉象及阴性信息；
- 诊次、干预、复诊、状态变化和结局；
- 原文值、OCR 或转录值、纠正候选及其依据；
- 无法确认的词句、缺失信息和文本质量；
- 历史诊断与历史治疗，和平台当前分析严格分开。

纠正候选不能覆盖原始值。标准病例是后续所有 Agent 和 Skill 的共同输入，避免不同分支各自改写患者事实。

## 5. 证据化多路径推理

系统不能从单个关键词直接跳到证型、诊断或治疗。每个候选假设和机制至少能够记录：

- 支持证据；
- 弱支持或低辨别力证据；
- 反证或歧义证据；
- 尚缺少的关键证据；
- 适用条件、时间和人群范围；
- 来源类型与原文位置；
- 生成方式、审核状态和可撤销的支持度。

病例中的数值置信度只能是特定评分体系下的排序或专家软标签，不得表达为未经验证的真实临床概率。模型、规则和专家给出的分值必须标明产生方法和版本。

证明树或证明图用于连接“结论—中间判断—证据”，但不能把模型自由生成的解释伪装成来源事实。困难负例、冲突特征和信息不足样本必须保留，用于防止关键词匹配和过早收敛。

## 6. 中医专业路径

中医分支在通用临床认知链上增加：

- 望闻问切及四诊信息完整性；
- 病因、病位、病性、邪正、寒热、虚实、气血津液和脏腑经络；
- 主病机、次病机、兼夹病机、病理产物和动态传变；
- 本标、主次、缓急、整体与局部等关系；
- 证候组合、鉴别、治则治法、方剂、药物和针灸；
- 通用病机、医家经验和个体医案三层对齐。

《内经》《难经》《伤寒论》等内容应作为有来源、可配置、可比较的经典方法与知识路径，而不是无条件的最高规则。例如可分别表达气血脏腑整体关系、脉经脏腑联动和状态传变方法；对于不适用的病例不得强行套入固定证名或方证。

“矛盾矩阵”可作为中医分支中的结构化分析工具，用于记录本虚与标实、推动与阻滞、温煦与凝滞、升运与壅滞、全身与局部、慢性与急变等并存关系。它用于发现约束、确定处理优先级和组合治疗目标，不自动证明某一方药或操作有效，也不替代常规鉴别与专家评审。

## 7. 西医专业路径与安全门

西医分支在统一主干上表达病史、危险因素、标准表型、检查、病理生理假设、诊断依据、鉴别诊断、风险分层、指南条件、干预和预后。历史西医诊断不能自动视为当前确认结论。

安全路径与中西医推演并行，且具有更高优先级：

```text
标准病例
  ├─ 安全分诊与红旗检测
  ├─ 西医表型 鉴别和风险路径
  └─ 中医四诊 病机和治法路径

安全门未通过
  → 阻断或降级高风险诊疗建议
  → 输出急诊 转诊 检查或人工复核要求

安全门通过
  → 继续授权范围内的中西医辅助分析
```

指南、标准和安全规则必须记录适用版本、日期、来源和作用域。中医解释、历史医案或模型置信度均不能绕过急危重风险处置。

## 8. 从治疗目标到实际干预

平台禁止采用简单的“疾病或证型直接对应方药、穴位或西医干预”。统一路径为：

```text
机制与综合状态
  → 治疗或处置目标
  → 治疗算子
  → 方剂 药物 针灸或西医干预候选
  → 适用条件 禁忌与安全检查
  → 实际行动
  → 状态变化与响应
```

治疗算子是对目标的抽象表达，例如补益、温通、活血、通络、调中、控制风险或进一步检查。算子评分只表示对当前机制和约束的匹配程度，不等同于临床疗效评分。

药物四气五味、归经、固有功效和安全信息进入可复用的 `HerbKnowledge`；剂量、炮制、方中角色、配伍关系、加减、停调和预期状态变化进入具体方剂上下文。方义不能由单味药属性简单相加得到。FormulaSkill 负责把治疗目标、整方药物层、适用状态和控制规则连接起来。

针灸同样采用“目标—算子—经络或机制—穴位”的关系，不能只训练“病名—穴位”的静态对应。

## 9. 病例状态轨迹与反事实

多诊次病例应构造：

```text
State_t + Action_t → State_t+1 → Response_t+1
```

同一病例过程可以按任务投影为线性认知链、分支思维树、因果或关系图，以及加入诊次与状态变化的多维时序图。导师所述“思维链、思维树或四维图”统一落在同一底层图与时间状态模型上，不创建互相独立的数据副本；“四维”的具体维度和可视化方式在物理 Schema 与原型验证阶段确定。

状态同时保留中医与西医子状态、当前冲突、安全门、证据完整性和不确定性。实际历史治疗、平台候选建议和现代推荐路径必须使用不同字段和身份，避免模型把历史行为误学为当前正确建议。

没有复诊结果时只能保存初始状态和待观察项，不能虚构下一状态。反事实样本用于比较不同目标或算子覆盖了哪些机制、遗漏了哪些矛盾；它属于理论或合成候选，必须与真实疗效和真实随访分开。

## 10. 多智能体与 Skill 编排

平台基线保留以下六类逻辑职责：

1. OrchestratorAgent：任务拆分、路由、状态、失败恢复和汇总；
2. KnowledgeBuilderAgent：组织材料摄取、证据抽取、病例标准化、知识蒸馏和知识包候选；
3. TCMReasoningAgent：四诊、病机、三层对齐、证候、治法及经典方法路由；
4. WesternReasoningAgent：表型、病理生理、鉴别、检查和风险路径；
5. EvidenceReviewAgent：支持、反证、缺失、冲突、证明图和质量检查；
6. SafetyGovernanceAgent：红旗、权限、隐私、版权、禁忌、高风险阻断和发布治理。

最小实现只启用 OrchestratorAgent、KnowledgeBuilderAgent 和 EvidenceReviewAgent。确定性的版本、持久化和发布由平台服务完成，不为这些操作强行增加 Agent。

运行时可按任务并行调用中医、西医与安全路径，由总控 Agent 汇总；构建期则按摄取、抽取、构造、评审和发布状态机推进。后续只有在以下条件下拆出更多 Agent：需要独立权限、独立状态、独立模型、并行吞吐、专门工具或可单独评价。OCR、术语规范化、经典方法、方剂、针灸、指南核验、反事实、训练数据构建和模型评测等均可在成熟阶段拆分。

Skill 可比 Agent 更细，例如病例标准化、安全分诊、生物医学表型、中医四诊、经典方法、病机推断、冲突分析、证候组合、目标规划、方剂分析、针灸分析、证据核验、状态预测和反事实分析。它们必须声明输入、输出、证据要求、失败语义、权限和版本。

## 11. 可重建的任务与训练数据视图

一个病例可以从同一事实和过程对象生成多种任务视图：

1. 原始病例到标准病例；
2. 原始描述到标准表型；
3. 红旗与安全分诊；
4. 四诊信息结构化；
5. 西医假设与鉴别；
6. 病机或病理生理机制推断；
7. 机制到证候或诊断候选；
8. 冲突、主次和优先级分析；
9. 机制到治疗或处置目标；
10. 目标到治疗算子及干预候选；
11. 当前状态与行动到下一状态；
12. 错误推理负样本、偏好对和反事实比较。

这些视图可以服务评测、监督微调、偏好对齐、工具调用或其他未来任务，不应笼统地全部称为预训练数据。当前阶段只保存可重建它们所需的事实、血缘、审核、许可、负样本和错误类型；正式样本的格式、数量和训练用途在核心链跑通后另行审批。

## 12. 质量与安全约束

- 不输出或保存模型不可审计的隐藏思维链，只保存证据化路径、结构化中间状态和可复核决策摘要；
- 不把专家软标签、模型分数或路径支持度表述为真实临床概率；
- 不把个案、历史疗效、反事实或模型预测升级为普遍医学事实；
- 不把历史治疗等同于现代推荐，不让中医路径绕过现代急症安全门；
- 不把中医和西医机制强行等同，只在有依据时建立受控关联；
- 不让 Agent 或 Skill 直接修改已发布知识库，所有写入经过版本化服务、质量门和人工权限；
- 不因使用多个 Agent 而重复制造事实副本，所有角色引用同一证据和病例状态；
- 不在需求评审阶段提前锁定物理字段、模型、Agent 数量或部署进程。
