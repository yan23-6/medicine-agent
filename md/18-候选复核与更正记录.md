# 候选复核与更正记录

## 当前目的

把已经生成的中医候选变成可逐条核对的对象，展示原文、位置、解释、字段状态与待查问题，并记录用户的确认、退回或否定。三页候选曾用于试用，是可替换样本；本轮软件使用自制材料检查，不继续整书，不依赖尚未确认的临床推理基线。

用户对 T02-P 的暂时认可仅适用于资料分析首版功能，不代表确认所有知识点或通过医学验收。T02-A 临床基线仍为 review，临床教材金标准任务仍需原有进入门。

## 不覆盖的复核层

来源节点和 facts 保持原样，用户意见独立保存在包内 `reviews/` 资源；B2单文件接口生成包含历史的新文件，复制该文件即可迁移。目录API只保留内部兼容。用包 ID、节点 ID、分组 ID、字段序号及内容指纹定位；不能只用名称或字段名称定位同名、多次出现的事实。

复核分节点和字段两种范围。节点确认不能自动确认所有字段；字段确认也不确认整节点。记录包含决策、理由、可选更正候选、用户填写的复核者、UTC 时间、前一条记录、目标指纹和内容校验。复核者身份是用户声明，不能当已认证专家身份。

确认、需修改、否定是用户复核意见，单独显示为 user_review_state；不改写节点 unreviewed、原文/OCR、推断状态或平台 medical_review。更正只保存候选，不自动替换旧值或升格为正式金标准；后续正式修订须另经版本化产包与原有校验。

每次意见追加新记录。显式校验 expected_previous_id，避免两个写入者覆盖对方；分支、缺失历史或篡改记录必须显示异常，不能擅选一条当最终结论。目标包卸下后保留意见及地址，放回后可重新解析；改变知识或证据内容身份的修订不继承旧确认。完全相同的内容副本仍识别为同一稳定地址。

## 清单与质量提示

清单按节点/字段展示来源、物理页、原始引文、当前值、状态和理由。优先提示模型推断、歧义、低置信 OCR、跨页、节点缺口及同一分组内反复出现同名字段；提示是核对线索，不是系统自动判断医学错误。

历史自动覆盖提示可能误报，应与模型实际报告缺口区分。不能删除历史原文或根据“被引用”声称整段已经理解。初始清单不自动写入任何确认意见。

## 契约与范围

唯一语义仍在 `src/medicine_agent/semantics/registry.json`；新增复核记录/目标寻址语义先登记，再实现与导出独立 review 契约。既有中医图 0.3.0 字段意义不变，旧包继续可读。

复核层提供运行时 API、CLI、可迁移记录、检查与可读核对清单；明确意见的候选修订由下文独立契约承担。两者不交付医学结论、专家身份认证、自动更正发布或完整 Web 审核界面。


## 2026-10-15 核对后推进

用户已认可本轮辅助核对流程。候选修订属于独立的后续运行时能力：明确意见与精确目标作为实际修改前置，建设阶段允许用自制意见测试，无意见不制造修改。新修订必须保存父版本、修改对照、原文/OCR、来源与证据；旧版及意见历史可回查，失败不影响旧版使用。具体正式执行范围见 CURRENT_TASK；追加资料的增量更新另行评审。


## 候选修订 0.1.0 实施约定

产品修订入口为总智能体 `revise_candidate`、`FileLearningService.revise` 和 CLI `analyze revise`；输入父包文件名及复核记录ID。内部仍复用 `PackageCatalog.revise_candidate`，目录参数仅为兼容接口。仅接受当前有效历史的最新“需修改”意见，必须带明确 proposed_value；同一目标重复或节点与其字段重叠时拒绝。节点字符串修改 statement；对象仅允许 title、statement、aliases、topics、categories。字段默认仅替换 value；显式 `{"fact_patch":{"value":...,"state":...,"reason":...}}` 可修改值、状态及理由，仍受原 Schema 和证据校验。空值用 fact_patch 显式表达。原文、引文、来源、分组、缺口均不可经此入口改写，不能冒充重分析。

以父包身份及排序后的复核 ID 确定新版身份，重复提交返回相同产物；已失效或被新意见替代的请求仍拒绝。先在私有快照生成并校验，再原子提交独立 .medpkg 文件；失败保留旧版和可读缓存，不产生可见半包。文件目录默认选择每条来源线的最高有效版本；已有显式 select 固定选择优先，可切回旧版。B1内部目录接口仍保持显式选择规则。文件可被检索不等于医学审核通过或正式发布。

`corrections.json` 为受 manifest 校验和保护的独立 0.1.0 操作契约，保存各次父图、父版本、明确意见、节点前后 ID 对应与继承文件校验和。查询返回 correction_provenance；卸下父包仍能查本版修改前后和证据。B2自包含派生文件内同时保留 reviews、links、继承来源及更正历史；只迁移该文件即可。旧关联地址继续指向旧包，不自动转接新版或复制确认。TCM 图及原始投影中的 generation_method 保留初次提取的模型来源；它不描述最后一次修订，实际修改来自 user_entered，必须结合 corrections.json/查询 provenance 展示。新版医学状态仍 unreviewed。

医学字段字典及既有 TCM/复核契约不变；新增的是操作契约，不新增另一套医学字段解释。B2已经接入多基础文件学习，保留有效更正与所有原文；精确处理缓存不用于跳过新资料的同名概念。
