# 候选复核与更正记录

## 目的

把已经生成的中医候选变成可逐条核对的对象，展示原文、位置、解释、字段状态与待查问题，并记录用户的确认、退回或否定。对资料分析软件的认可不代表确认全部知识点或通过医学验收。

## 不覆盖的复核层

来源节点和 facts 保持原样，用户意见独立保存在包内 `reviews/` 资源；单文件接口生成包含历史的新文件，复制该文件即可迁移。目录 API 只保留内部兼容。用包 ID、节点 ID、分组 ID、字段序号及内容指纹定位；不能只用名称或字段名称定位同名、多次出现的事实。

复核分节点和字段两种范围。节点确认不能自动确认所有字段；字段确认也不确认整节点。记录包含决策、理由、可选更正候选、用户填写的复核者、UTC 时间、前一条记录、目标指纹和内容校验。复核者身份是用户声明，不能当已认证专家身份。

确认、需修改、否定是用户复核意见，单独显示为 user_review_state；不改写节点 unreviewed、原文/OCR、推断状态或平台 medical_review。更正只保存候选，不自动替换旧值或升格为正式金标准；后续正式修订须另经版本化产包与原有校验。

每次意见追加新记录。显式校验 expected_previous_id，避免两个写入者覆盖对方；分支、缺失历史或篡改记录必须显示异常，不能擅选一条当最终结论。目标包卸下后保留意见及地址，放回后可重新解析；改变知识或证据内容身份的修订不继承旧确认。完全相同的内容副本仍识别为同一稳定地址。

## 清单与质量提示

复核准备使用独立review-preparation管理契约，不修改既有ReviewRequest/ReviewRecord。原文标注包含全部证据，不限于被引用部分；候选对照保存完整ReviewTarget、目标指纹及expected_previous_id，gap和隔离项保存为独立审计材料，不可直接作为review-record输入。所有新评审模板为空，旧用户意见与新模板分开；无法判断、缺评审者或缺医学审核不得升级确认。只读准备API不登记成新Agent/Skill，导出只写新目录，完整/部分/空结果必须显式区分且不覆盖既有文件。

清单按节点/字段展示来源、物理页、原始引文、当前值、状态和理由。优先提示模型推断、歧义、低置信 OCR、跨页、节点缺口及同一分组内反复出现同名字段；提示是核对线索，不是系统自动判断医学错误。

历史自动覆盖提示可能误报，应与模型实际报告缺口区分。不能删除历史原文或根据“被引用”声称整段已经理解。初始清单不自动写入任何确认意见。

## 契约与范围

唯一语义仍在 `src/medicine_agent/semantics/registry.json`；新增复核记录/目标寻址语义先登记，再实现与导出独立 review 契约。既有中医图 0.3.0 字段意义不变，旧包继续可读。

复核层提供运行时 API、CLI、可迁移记录、检查与可读核对清单；明确意见的候选修订由下文独立契约承担。两者不交付医学结论、专家身份认证、自动更正发布或完整 Web 审核界面。


## 准备快照与独立复核会话边界

复核会话创建前必须读入并验证准备目录的资源集合、路径、版本、原始字节哈希和稳定ID，再从相同字节的源包重建报告，核对来源、材料、目标指纹、历史和计数；展示Markdown须与报告一致。自报哈希只能证明自洽，不能替代源包核验。快照、源包、私有缓存和会话目录分离，失败不创建会话或写部分意见。完整/部分/空准备结果保留各自语义，未支持的状态明确拒绝，不自动补齐。返回的验证对象不构成专家认证或永久授权。

独立会话意见按声明评审者与材料地址追加，无法判断单列；同一评审者多次提交不算多名专家。原文标注、候选和异常分开寻址；gap/隔离项不能转换为ReviewTarget。准备表始终为空，新意见由独立输入承载。分歧保留每人理由，不由时间、票数或模型偏好生成医学结论；仲裁权限未成立时保持待仲裁。此为会话设计约束，具体已实现范围以代码和验收为准。

独立会话使用review-session/0.1.0操作契约，与包内review/0.1.0分离。每批提交一名声明评审者、同一快照的1—1000项不同材料意见；按评审者与材料保留前序。评审者ID去首尾空白并统一大小写，避免同ID大小写变化被算作第二人，仍无法自动认证别名或真实身份。一致性视图只比较不同声明ID的最新明确决定及纠正候选，无法判断单列，分歧必须待仲裁，不产生医学确认。纠正原文仅存字符串候选，异常审计不能携带可发布修正。类型模型不替代运行时快照、内容哈希、事务和历史校验；实际能力以验收为准。

## 明确意见与候选修订

候选修订是独立运行时能力：明确意见与精确目标作为实际修改前置，软件测试允许使用自制意见，无意见不制造修改。新修订必须保存父版本、修改对照、原文/OCR、来源与证据；旧版及意见历史可回查，失败不影响旧版使用。追加资料的增量更新由文件学习流程处理。


## 候选修订 0.1.0 实施约定

产品修订入口为总智能体 `revise_candidate`、`FileLearningService.revise` 和 CLI `analyze revise`；输入父包文件名及复核记录ID。内部仍复用 `PackageCatalog.revise_candidate`，目录参数仅为兼容接口。仅接受当前有效历史的最新“需修改”意见，必须带明确 proposed_value；同一目标重复或节点与其字段重叠时拒绝。节点字符串修改 statement；对象仅允许 title、statement、aliases、topics、categories。字段默认仅替换 value；显式 `{"fact_patch":{"value":...,"state":...,"reason":...}}` 可修改值、状态及理由，仍受原 Schema 和证据校验。空值用 fact_patch 显式表达。原文、引文、来源、分组、缺口均不可经此入口改写，不能冒充重分析。

以父包身份及排序后的复核 ID 确定新版身份，重复提交返回相同产物；已失效或被新意见替代的请求仍拒绝。先在私有快照生成并校验，再原子提交独立 `.medpkg` 文件；失败保留旧版和可读缓存，不产生可见半包。文件目录默认选择每条来源线的最高有效版本；已有显式 select 固定选择优先，可切回旧版。内部目录接口仍保持显式选择规则。文件可被检索不等于医学审核通过或正式发布。

`corrections.json` 为受 manifest 校验和保护的版本化操作契约，保存各次父图、父版本、明确意见、节点前后 ID 对应与继承文件校验和。查询返回 `correction_provenance`；卸下父包仍能查本版修改前后和证据。自包含派生文件同时保留 reviews、links、继承来源及更正历史；只迁移该文件即可。旧关联地址继续指向旧包，不自动转接新版或复制确认。TCM 图及原始投影中的 `generation_method` 保留初次提取的模型来源；实际修改来自 `user_entered`，必须结合更正记录展示。新版医学状态仍为 `unreviewed`。

医学字段字典及既有 TCM/复核契约不变；新增的是操作契约，不新增另一套医学字段解释。多基础文件学习必须保留有效更正与所有原文；精确处理缓存不用于跳过新资料的同名概念。


## 用户归属与联合使用边界

后续增量复用不得用初始模型缓存覆盖用户更正；应将最终有效更正作为基础内容继承，不得静默丢弃修改；尚不支持的精确缓存优化不能作为禁止继续学习的产品权限。归属和联合查询设计见第19章。
