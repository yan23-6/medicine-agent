# 方剂药物层与后训练规划

本文固定方剂与药物层的 Skill 组织方式，并规定后训练如何进入项目周期。当前阶段只固化后训练的目的、边界、启动条件和未来方案形成流程，不提前确定基础模型、训练框架、样本数量、超参数、算力、验收阈值和安装命令。等智能体结构、知识蒸馏结构及核心链路实际跑通后，再依据届时项目状态形成可执行的后训练与验收方案。

本章服从平台最高级架构：Agent 负责协作和决策，Skill 负责具体能力，统一知识包与病例数据模型负责保存事实和状态。FormulaSkill 是可被中医推理 Agent、评审 Agent 和其他授权角色调用的组合能力，不等同于一个必须独占模型或进程的 Agent。

## 1. 方剂与药物层的固定设计

一个方剂对应一个可部署、可版本化、可评审的组合式 FormulaSkill。方剂识别、病机解释、药物层、加减、状态转移、停调、方剂选择和方剂比较是 FormulaSkill 的内部能力，不拆成需要分别安装的顶层 Skill。

```text
FormulaSkill
  ├─ 方剂识别
  ├─ 病机解释
  ├─ DrugLayerSkill
  │    ├─ HerbUnit A
  │    ├─ HerbUnit B
  │    ├─ HerbUnit C
  │    └─ 配伍 剂量 炮制 安全与共同作用
  ├─ 加减
  ├─ 状态转移
  ├─ 停止与调整
  ├─ 方剂选择
  └─ 方剂比较
```

DrugLayerSkill 在方剂范围内统一管理多味药物单元和整方配伍关系。单味药的名称、来源、固有属性和安全信息可以通过 HerbKnowledge 跨方复用；剂量、炮制、用法、方中角色、配伍对象、条件加味和作用靶点通过 FormulaHerbRole 绑定具体方剂与适用状态。

系统不能把多个单味药功效简单相加后当成方义，也不能把某味药在一个方中的作用复制为所有方中的通用角色。

## 2. 所有 Skill 服务同一核心链

平台中的知识蒸馏、问诊、病机、方剂、药物、评审和安全 Skill 不是互不相关的功能集合。它们共同服务以下核心链：

```text
医学材料
  → 知识蒸馏与证据化
  → 可版本化知识包
  → 原始病例到标准病例
  → 临床观察与问诊补充
  → 中西医多假设与专业机制
  → 支持 反证 缺失 冲突与安全门
  → 综合状态
  → 治疗目标
  → 治疗算子
  ├─ 方剂候选 → 整方药物层 → 加减与停调
  ├─ 针灸候选 → 经络机制与穴位组合
  └─ 西医干预候选 → 适应证 禁忌与指南条件
  → 实际或候选行动
  → 预期目标状态
  → 随访观察
  → 重新问诊和辨证
```

知识构建类 Skill 为核心链提供可信知识；临床推演类 Skill 执行问诊、辨证和治疗决策支持；方剂药物类 Skill 连接方、药和状态变化；治理类 Skill 控制证据、评审、版本、权限和安全。

## 3. 当前阶段对后训练的定义

后训练是在选定基础模型后，使用项目产生的已审核任务样本继续训练或对齐模型，使模型更稳定地执行项目任务。后训练不负责保存全部医学事实，也不替代知识包、Skill、检索、专家评审和安全守门。

当前只固定以下分工：

| 部分 | 固定职责 |
| --- | --- |
| 知识包 | 保存可更新、可追溯的医学事实、来源、冲突和版本 |
| Skill 与规则 | 规定任务步骤、工具调用、质量门和确定性约束 |
| 智能体编排 | 由 Agent 根据核心链并行或串行调用不同 Skill、管理状态并作出受控决策 |
| 后训练 | 提高结构化执行、证据边界、工具使用和安全行为的稳定性 |

当前不把某种模型、LoRA、QLoRA、监督微调、偏好优化或其他算法固定为必须实现的技术路线。这些方法只作为未来候选，届时根据实际模型许可、数据质量、部署环境、算力和基线错误决定。

## 4. 为什么现在不固化具体训练方案

训练任务和验收标准必须依赖真实项目结构。如果现在提前确定，很可能出现以下问题：

- 智能体最终的角色、工具和状态接口尚未稳定，训练样本无法对应真实调用方式；
- 蒸馏对象、证据字段和知识包 Schema 仍可能变化，提前生成样本会形成错误数据债务；
- 核心链尚未端到端运行，无法判断错误来自知识、检索、Skill、编排还是模型；
- 没有稳定基线时，无法给出有意义的训练提升和验收阈值；
- 基础模型、部署方式、许可、硬件和预算尚未确定，安装与训练命令无法可靠固化。

因此，当前文档保留后训练思路和数据血缘要求，但不把未来实现猜成已经确定的方案。

## 5. 后训练启动前置条件

只有以下条件基本满足，项目才进入“后训练方案设计阶段”：

1. 智能体角色、工具、输入输出和状态流已经确定，并能端到端完成一次核心任务；
2. 知识蒸馏流程、证据对象、知识包结构和版本机制已经实现并可重复运行；
3. 病例标准化、中医与西医专业路径、安全门、方剂、统一药物层、加减、状态变化和停调能够在核心链中完成一次可审计闭环；
4. 知识错误、检索错误、Skill 错误、编排错误、模型错误和安全错误已经可以区分；
5. 已建立未训练模型、检索增强和 Skill 编排的可复现基线；
6. 已有一定数量经过专家审核、许可明确、能够回到证据的任务记录和错误样本；
7. 测试集、医学安全集和必要的专家评审流程已经建立；
8. 候选基础模型、运行环境、数据许可、算力、预算和权重发布范围已经明确。

前置条件未满足时，反馈主要用于修复知识包、Schema、检索、规则和 Skill，不启动正式后训练。

## 6. 未来方案如何从项目状态生成

进入后训练方案设计阶段时，先冻结一个可复现的项目快照，包括：

- 智能体角色、工具、状态机和核心链版本；
- 知识包协议、蒸馏结构、证据结构和 FormulaSkill 版本；
- 当前基础模型、提示、检索、规则和安全策略；
- 已知错误类型、人工修改记录和任务失败分布；
- 可用数据及其许可、审核和风险状态；
- 测试集、专家评审方法、部署环境、硬件和预算。

AI 再根据这个快照生成《后训练实施与验收方案》。方案不能套用当前文档中的假设，而必须逐项对应当时已经实现的模块和接口。

## 7. 未来必须生成的具体方案内容

届时形成的实施方案至少需要明确：

1. 后训练要解决的具体错误，以及不属于训练问题的错误；
2. 需要训练的智能体任务、Skill 调用和输出 Schema；
3. 训练样本如何从届时的知识包、运行记录和专家修订中生成；
4. 如何分别构造病例标准化、表型、安全分诊、中西医机制、证明图、冲突、目标、算子、状态预测、工具调用、负样本、偏好对和反事实等任务视图；
5. 数据纳入、排除、去重、脱敏、许可、审核和版本规则；
6. 按来源、医家、方剂族和完整病例划分训练、验证和测试的方法；
7. 候选基础模型、训练方法、训练框架、硬件、依赖和成本估算；
8. 数据转换、训练、断点、日志、模型注册和结果复现步骤；
9. 离线指标、专家评审、安全红队和端到端任务验收；
10. 与未训练、检索增强和 Skill 编排基线的对照方式；
11. 灰度范围、监控指标、停止条件、回滚方式和责任边界；
12. AI 安装和执行需要的权限、命令、产物、检查点和失败处理；
13. 数据卡、模型卡、评测报告和发布记录模板。

具体样本数量、指标阈值和硬件配置必须依据届时基线、数据分布和安全要求确定，不在当前阶段虚构固定数值。

## 8. 未来验收原则

当前只固定验收类别，不固定具体阈值。未来方案需要根据届时基线为每个类别设定可执行指标：

- 任务效果：核心结构化任务和端到端链路是否改善；
- 证据忠实：原文、整理、模型候选和专家确认是否正确区分；
- 工具使用：模型是否正确选择和调用知识包、Skill、评审与安全工具；
- 方剂药物：组成、药物层、配伍、加减、状态变化和停调是否正确；
- 泛化能力：未见来源、医家、方剂、病种和表达变化是否可接受；
- 医疗安全：越权诊断、患者自助处方、剂量、禁忌、停药和急症处理是否不退化；
- 工程质量：训练可复现、模型可注册、服务可部署、故障可定位；
- 运行稳定：灰度期间的错误率、人工修改量、延迟和资源消耗是否符合要求。

安全关键指标采用硬门槛，不能用其他平均分抵消。模型在部分任务上提高，但证据忠实或医疗安全退化时，仍判定为不通过。

## 9. AI 安装和执行的时间点

AI 不在当前阶段安装训练框架或启动训练。未来流程固定为：

```text
智能体与蒸馏结构跑通
  → 冻结项目快照
  → AI 生成后训练实施与验收方案
  → 项目负责人和医学专家审核
  → 确认数据许可 算力 成本和权限
  → AI 按批准方案安装依赖并建立训练环境
  → 执行数据构建 训练和评测
  → 专家与安全验收
  → 灰度发布或返工
```

AI 的安装权限只在实施方案批准后授予。安装与训练必须使用锁定版本、受控数据和可回滚环境，不得因为“自动化”跳过专家、安全、许可或成本审批。

## 10. 当前阶段需要保留的资产

虽然现在不训练，但项目从一开始就要保留未来训练所需的资产：

- 原始证据、结构化结果和模型候选之间的对应关系；
- 专家接受、拒绝和修订的差异；
- 每次任务实际调用的知识包、Skill、模型、提示和规则版本；
- 失败类型、人工修改量和安全拦截原因；
- 数据许可、隐私、版权、风险和可训练范围；
- 可复现的未训练、检索增强和 Skill 编排基线；
- 测试集候选及其隔离状态。
- RawCase 与 CanonicalCase、历史诊断与历史治疗、平台候选、实际行动和多诊次状态轨迹；
- 支持、弱证据、反证、歧义、缺失、证明图、错误负样本和专家软标签的来源及评分方法；
- Agent 路由、Skill 调用、并行路径、安全门和失败恢复记录；
- 反事实和状态预测的合成身份，防止与真实疗效或真实随访混合。

这些资产用于未来生成训练方案，不代表已经获准进入训练集。普通对话、未审核病例和许可不清材料默认不得直接用于训练。

## 11. 当前阶段交付结论

本阶段完成以下决策即可：

- FormulaSkill 和统一药物层的逻辑边界确定；
- 多种 Skill 共同服务同一核心链；
- 后训练的目的、边界、前置条件和治理要求确定；
- 当前不固定具体训练技术、数据量、验收阈值和安装步骤；
- 未来必须基于已跑通项目的真实快照重新生成实施与验收方案；
- 只有方案经过项目负责人、医学专家和安全治理审核后，AI 才执行环境安装与后训练。

这使后训练保留为项目的正式阶段，同时避免在智能体结构和蒸馏结构尚未稳定时提前形成不可执行的训练设计。
