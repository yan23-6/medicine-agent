# 产品目标与边界

本项目的产品目标是中西医知识蒸馏与智能体平台。通用医学主干负责材料、证据、病例、时间、评审、安全和版本，中医与西医分别在该主干上增加自身的方法、概念和知识。当前数据和论文验证以中医病机为重点，不代表平台最终只服务中医。

## 1. 要解决的问题

中医教材、名医著作和医案之间通常存在三种割裂：理论分类无法直接连接名医经验，名医经验无法系统回到具体病例，病例中的辨证过程又常被压缩为病名、证型或处方。普通文档检索只能找到相似段落，难以解释医家为什么形成某个病机判断、哪些证据支持它、它如何随诊次变化。

西医材料同样存在知识、指南、病例与临床过程割裂的问题。平台以共享证据和病例状态为基础，让中医病机路径与西医表型、病理生理、诊断、鉴别、风险和干预路径并行运行，同时保留各自理论边界。

本平台以病机为中轴，解决以下问题：

- 从多格式材料中精细抽取知识和来源推理片段；
- 将原始病例标准化为中西医路径共同使用的病例事实与时间线；
- 把通用病机、名医经验和具体医案对齐；
- 在同一病例中并行组织中医病机路径、西医临床路径和高优先级安全路径；
- 保存病机的主次、兼夹、时序、转化、反证和适用条件；
- 让知识包可独立检索，也可组合形成病机路径；
- 把“症—证—机—法—方—药—效”组织为可审计的方剂认知与控制路径，并保留加减、停调和随访状态变化；
- 用医案和专家评审积累条件化经验支持；
- 让同一套能力可以在独立 Web 和多种智能体环境中使用。
- 由 Agent 负责任务协作和决策，由 Skill 提供具体能力，并通过统一知识包与病例数据模型交换状态；
- 在材料和科目持续增加时，仍保持无需单独安装数据库、无需 Docker、无需额外数据库服务的即插即用体验。

## 2. 目标用户

平台目标用户包括中西医研究人员、研究生、教师和获得授权的临床专业人员；当前首个研究闭环主要面向中医相关用户。普通公众只能使用安全受限的健康教育与就医建议模式。

不同用户看到的深度和可执行能力不同：

- 研究人员：查看知识结构、来源、冲突、版本和实验指标；
- 教师与学生：学习病机分类、医家差异和医案推演；
- 临床专业人员：获得带出处的病例讨论和鉴别辅助；
- 评审专家：修正抽取、对齐和路径，签署审核结果；
- 管理员：管理包、模型、权限、安全策略和发布流程。

## 3. 产品产物

平台正式产物包括：

1. 一套项目级统一知识包协议说明书，统一解释全部兼容数据包的数据语义、使用方式、质量状态、兼容规则和安全边界；
2. 按统一协议生成、可独立安装到兼容平台并查询的医学知识数据包；每个包只携带机器识别所需的最小自描述信息，不重复生成包级说明书；
3. 基于知识包构造的病机图、三层树和病例链；
4. 抽取、对齐、评审、错误与版本报告；
5. 独立 Web 应用、MCP 服务、REST API 和环境适配包。
6. 可由知识包生成、可评审和可版本化的 FormulaSkill 数据视图，以及为未来后训练保留的证据血缘、专家修订、错误样本候选和可复现基线。具体训练数据集与模型版本在智能体和蒸馏结构跑通后另行设计。
7. 可审计的标准病例、临床认知图和多诊次状态轨迹，以及由同一事实层重建的多任务数据视图。
8. 可扩展的多智能体编排方案；平台保留六类职责，MVP 在 Skill 闭环稳定后先启用编排、知识构建和证据评审三个逻辑角色，其余按进入条件启用。

运行平台默认内嵌 LadybugDB。用户安装平台或对应智能体适配包后即可使用数据库能力，不承担数据库环境搭建和服务维护工作。

## 4. 不属于本项目的目标

- 不构建替代医生的自动诊断系统；
- 不面向患者自动开方、确定剂量或替代既有治疗；
- 不把所有中医流派强行统一成一个结论；
- 不把模型自由生成的推理当作医家原意；
- 不以病例数量直接证明治疗有效或病机正确；
- 不把全部医学内容塞进提示词或 Skill；
- 不为每味药发布一个相互孤立的顶层 Skill，也不把单味药的通用功效直接等同于其在具体方剂中的配伍作用；
- 不把后训练后的模型权重作为唯一医学知识库，不让模型记忆替代来源证据和知识包更新；
- 不在首版覆盖所有科室、全部医家和所有材料格式。
- 不把中医病机和西医病理生理或诊断概念强行声明为同义；
- 不把模型隐藏思维过程作为数据产物，只保存可回溯的证据化路径、结构化状态和决策摘要；
- 不以智能体数量作为系统能力指标，也不要求一个 Skill 对应一个 Agent；
- 不要求一个未经处理的数据库文件夹被不同智能体直接读取；智能体通过平台提供的受控能力访问已启用知识包。

## 5. 成功标准

系统只有同时达到以下结果才算成功：知识可回溯、病例可标准化、三层可对齐、路径可审计、冲突和缺失可保留；通用主干可以同时支持中医与西医专业对象且不混淆语义；中医、西医和安全路径能围绕同一病例受控协作；Agent、Skill 和数据层职责清楚；组合式 FormulaSkill 能在同一药物层中解释多味药的固有属性、方中角色、配伍关系、条件加减和停调规则；任意符合统一协议的普通新包无需新增说明书或修改核心智能体，复制后即可被平台自动发现并联合使用；不同环境可调用、默认运行不依赖外部数据库服务；核心链和未训练、检索增强、Skill 编排基线可以复现，并能为未来基于真实项目状态制定后训练方案提供完整数据。
