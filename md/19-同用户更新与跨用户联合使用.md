# 多包基础上的增量学习与完整来源保留

> 现行稳定需求：2026-10-15 用户再次澄清。
> 撤销“不同作者不能更新父包/不能作为更新基础”的限制。B2单文件运行入口已完成软件验收（2026-10-16），记录见当前阶段 T02B2_ACCEPTANCE.md。

## 1. 作者不是更新权限

任何用户都可以导入、使用并基于其他人的兼容数据包继续学习。包的制作者、当前操作者和原始材料作者是不同概念，均属来源/贡献记录，不能变成阻止知识更新的权限条件。学习资料生成数据包不是模型权重后训练。

## 2. 尚未继续学习时

用户1的包1和用户2的包2放同一数据根目录，整体智能体就能联合检索内容和关联。两边关于“气”的来源节点、解释、字段、原文/OCR及位置全部保留，建立关联后可共同分析，不以一个包替换另一个包。不得把别人的成品包冒充新书输入，通过去重/追加流程丢掉其内容。

## 3. 用户3用新书A继续学习

包3的逻辑内容 = 包1全部有效内容 + 包2全部有效内容 + A的新增知识、补充解释及关联。

- A也讲“气”：仍须读取、分析并保存A的原话，不能因为旧包已有该概念就跳过。统一概念入口关联包1、包2及A的三个独立来源节点，保留每个来源的完整字段、条件、原文、定位和解释。术语对齐属于候选关联，不凭同名覆盖、抹平分歧或自动判定定义完全一致。
- A讲旧包没有的“热”：包3新增A的知识节点及对应原文来源。
- A没涉及的旧知识：包3继续继承原内容及来源，不删除、不重新编造。
- A与旧知识冲突：并列保留各自主张和证据，记录冲突/适用条件，不用新来源静默覆盖旧来源。

包3交付为一个独立数据包文件，复制到智能体固定数据目录即可发现和读取。文件内自包含必要基础数据、原文证据、关联和血缘，不依赖开发机路径或包1/2仍在原位置。内部来源分区仅为封装实现，不能把目录作为最终数据包交付。包1和包2原件保持独立，不因生成包3而被改写。

## 4. 增量学习与处理缓存分开

本次增量指在已有完整知识基础上更新和补充，不是只读取“尚未出现的概念”。成品数据包作为基础知识导入，PDF等资料作为新来源读取，两类输入必须区分。

同一文件已完成页的暂停续跑/精确缓存复用是独立效率机制。仅由原文件指纹、分析配置、范围、上下文及更正状态判断有效性，作者身份不构成更新权限。缓存无效时保留基础知识并重读相应资料，不能把拒绝优化变成拒绝基于他人包继续学习。

## 5. 数据结构与实现边界

保留来源节点层：每个包/资料的原始节点、所有字段及证据独立可回查；增加统一概念/关联视图和派生包血缘，表达共同概念、补充、冲突和新增内容。分类可以在视图中汇总，来源分类不覆盖。具体统一关系不得成为另一套医学字段字典，医学字段仍以唯一语义注册表为准。

当前已有多基础文件学习、自包含单文件产包、固定目录发现和统一候选概念视图。作者限制已从运行入口撤销；原始来源节点、分类、证据和历史分别保留。概念匹配目前依据规范化名称/别名，仅为候选关联，不能代替医学语义审核。软件检查见 T02B2_ACCEPTANCE.md；不沿用旧作者限制实验的通过记录。

## 6. 验收必须覆盖用户例子

使用两个不同制作者的包，包含两个“气”节点和各自独有旧知识；第三人从A分析“气”和“热”。确认第三人可以更新；包3含全部旧知识、“气”的三个独立原文/字段集和统一关联、新“热”节点；移走包1/2及任务缓存后包3仍可查全来源、分类、关联与更正历史；旧包原件不变；语义冲突不静默覆盖。

临床、正式格式和数据库功能继续按原阶段门验收。三页教材结果仅为可替换试验样本，不是最终交付物。


## 7. 最终交付与固定发现目录

每个数据包是一个独立文件；本轮暂用 `.medpkg` 作为产品后缀。数据包不是用户要自行管理的多个文件组成的目录。包内序列化和归档细节由版本化契约约束，不影响用户复制单个文件使用。

默认固定发现路径为 `<用户目录>/MedicineAgent/knowledge/`，按用户目录解析为绝对路径，不受运行时工作目录影响。此目录同时存放兼容数据包文件和平台统一说明书：

```text
knowledge/
  数据包说明书.md
  package-spec.json
  包1.medpkg
  包2.medpkg
  包3.medpkg
```

说明书的人读/机器读表示均从项目唯一注册表和版本化契约生成，是同一套规范，不按每个包另造一套。每个包只带协议版本、身份、校验和、来源、内容及必要机器自描述。放入文件后平台在启动、读取前或刷新时发现并校验，纳入联合使用；移走后停止使用对应包文件的贡献。不兼容或损坏文件明确隔离，不能猜字段。移走原包1/2但保留自包含包3时，包3中继承的内容仍可用。

分析任务、暂停检查点、临时解包目录和索引缓存统一放内部工作区，与固定数据包目录区分；缓存可重建。使用者不需要解压、注册内部来源目录或复制开发缓存。

## 8. 文件输入输出与验收差距

`paths` 为PDF等新资料，`base_packages` 为成品数据包文件；二者不可混用。新资料仍完整读取，最终输出包3.medpkg。提交时校验基础文件并保存稳定快照，支持暂停重启；完整产包校验后原子放入固定发现目录，失败不覆盖原包。作者/操作者只记录贡献，不设更新权限。

包3保留包1/2全部有效来源节点、原文、分类、关联和更正历史，再加入新书A。共同概念有统一候选入口，但保留各来源解释及分歧；新概念新增；A未涉及的旧内容原样继承。内部封装可分区组织，外部始终只交付一个包文件。

运行入口为 OrchestratorAgent → FileLearningService → 已验收工具及确定性封装/加载服务；未新增 Agent 或 Skill。目录组件仅为内部构建与解包表示。最终 .medpkg 含受校验的来源资源、关联、复核、更正和基础包血缘快照；机器结构见 schemas/learning。

专项检查覆盖“气/热”、跨作者续建、完整来源继承、移走基础文件仍可用、导入/移除、损坏隔离、失败重试及独立安装。完整结果和限制以 T02B2_ACCEPTANCE.md 为准。正式数据库与其他后续阶段仍保持原进入门。
