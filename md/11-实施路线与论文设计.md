# 实施路线与论文设计

## 1. 最小可行范围

首版选择一个完整闭环：

- 一本基础病因病机教材，构造第一层；
- 一位资料完整的名医或一个流派，构造第二层；
- 一批能够从原始文本重建为标准病例、带复诊和转归且包含必要中西医信息的相关医案，构造第三层与病例状态轨迹；
- 一个边界明确的病种群或专科作为验证场景。
- 一个来源清楚、包含组成与至少一种加减或停调信息的典型方剂小集，用于验证组合式 FormulaSkill 和统一药物层。
- 一个小型西医兼容样本，用于验证通用主干、专业分支和安全门没有被写死为中医结构；
- 三个初始逻辑 Agent，以及后续按阶段启用的中医、西医和安全治理角色；所有 Agent 只调用已经实现并通过验收的 Skill。

完成后再接入第二位专家或第二个专科，验证热插拔、冲突保留和泛化能力。首版不要同时铺开全部科室。

## 2. 里程碑

### 阶段一：Skill 基础与最小生产消费闭环

- 确定 Skill manifest、机器 Schema、调用入口、错误语义、模型适配和测试规范；
- 实现材料摄取、证据定位、最小知识蒸馏、知识包构建校验、知识包查询和质量评价 Skill；
- 用许可明确的测试材料完成生产、校验、查询、来源回溯和往返测试；
- 当前阶段只生成实验知识包，不蒸馏整本教材，不实现多 Agent。

### 阶段二：中医金标准与专业蒸馏 Skill

- 确定首个专题、病机最小表达单元、关系集、对齐状态和标注指南；
- 从教材片段、医家材料和少量医案制作人工金标准；
- 实现 RawCase 到 CanonicalCase、CaseDistillationSkill 和 TCMReasoningSkill；
- 保存原值、纠正候选、诊次、历史诊断、历史治疗和文本不确定性；
- 使用阶段一的 Build、Validate、Query 和 Trace 验证专业输出。

### 阶段三：知识包 v0、三层结构与 LadybugDB

- 完成一个名医经验包和一个医案包；
- 生成病机链和三层候选映射；
- 建立人工审核与冲突处理。
- 根据真实输出冻结知识包 v0 物理格式；
- 实现 LadybugDB 导入、索引、查询、停用和回滚；
- 完成组合式 FormulaSkill 原型，在一个药物层中管理整方多味药，并区分药物固有属性与方中角色。
- 形成支持、弱证据、反证、缺失、冲突、目标、治疗算子、行动和状态变化的可审计病例认知图；
- 建立中医、西医与安全路径的并行路由，验证安全门能够阻断高风险后续建议。

### 阶段四：运行平台

- 完成 Web 浏览、检索和病例讨论；
- 实现包安装、卸载、升级和回滚；
- 提供 MCP 和 REST API；
- 生成至少两种智能体适配包。
- 先以编排、知识构建和证据评审三个逻辑 Agent 跑通端到端任务，再按进入条件启用中医、西医和安全治理角色；
- 验证默认运行不依赖独立数据库服务、Docker 或额外数据库环境。

### 阶段五：实验与验证

- 完成自动指标、专家盲评和安全测试；
- 比较普通 RAG 和完整系统；
- 完成消融实验；
- 比较单体、最小多角色和扩展多智能体方案，验证拆分收益而非比较 Agent 数量；
- 评价标准病例忠实度、证明图、目标—算子—干预一致性、状态轨迹和中西医语义隔离；
- 在条件允许时开展医生在环验证。
- 使用逐级放大的多科模拟数据评价 LadybugDB 的容量、索引、联合查询、安装和恢复表现。
- 在独立兼容环境中执行只复制数据包、不增加包级说明书的热插拔验收。

### 阶段六：后训练与受控发布

- 确认阶段一至阶段五的智能体结构、蒸馏结构、FormulaSkill、统一药物层和端到端核心链已经可重复运行；
- 冻结当时的项目快照、基线、错误分布、可用数据、许可、评测集、部署环境和资源条件；
- 由 AI 根据真实项目状态生成《后训练实施与验收方案》，明确训练对象、数据、方法、安装、成本、指标、灰度和回滚；
- 由项目负责人、医学专家和安全治理人员审核方案；
- 审批通过后，AI 才按方案安装训练环境、构建数据、执行训练和评测；
- 只有通过方案规定的独立测试、专家评审和安全验收后，模型才进入灰度发布。

后训练从项目早期开始积累证据血缘、专家修订和错误样本，但不在前五阶段提前固化训练方法。监督微调、参数高效微调、偏好对齐和安全对齐均为未来候选，由阶段六根据届时项目条件选择。

## 3. 论文科学问题

> 如何从异构中医文献中自动抽取病机原子及其证据，构造通用病机—名医经验—个体医案三层可审计推理图，并在保留医家差异和病机动态性的同时，实现可靠对齐、病例条件化支持与可插拔智能体调用？

## 4. 核心创新点

1. 面向病机的细粒度证据化蒸馏，而非普通分块和向量检索；
2. 唯一证据层之上的知识视图与病机推理视图；
3. 三层树形展示、底层图表达和病例链推演的统一；
4. 带条件、时序、反证和来源的跨层自动对齐；
5. 用病例和专家评审更新条件化经验支持度；
6. 多医家、多专科知识包的冲突保留和跨环境热插拔。

论文主创新以前四项为核心，第五项作为学习闭环，第六项作为系统与应用创新。上下文记忆属于支撑能力，不宜抢占病机主线。

LadybugDB 选型属于满足即插即用和规模扩展需求的工程决策，不应包装为医学算法创新；其价值通过可复现的部署、联合查询和规模测试体现。

## 5. 基线与消融

基线至少包括：原始长上下文、普通分块 RAG、仅知识节点系统、只有病机链但无三层对齐的系统，以及完整系统。

后训练实验在阶段六另设模型侧基线。具体比较组依据届时采用的方法确定，但至少保留未训练、检索增强和 Skill 编排基线，并将模型训练收益与知识结构、检索和规则收益分开报告。

消融至少移除：专家包、医案包、反证关系、时间关系、病例支持度和人工确认映射。比较每项设计对病机准确率、可解释性、医家隔离和安全性的贡献。

新增消融包括：移除病例标准化、证明图、冲突对象、安全并行路径、治疗算子层、状态轨迹，以及把多 Agent 合并为单一角色。比较其对事实保持、错误定位、专业语义隔离、推理审计、安全和资源成本的影响。

## 6. 防止数据泄漏

- 按书籍、医家或医案来源划分训练、验证和测试；
- 同一病例的全部复诊记录整体划分；
- 设置未见医家、未见病种和未见表述测试；
- 保留同名异义、相似证、同方异证和同病异治困难负例；
- 锁定测试集后再调整规则；
- 记录数据、模型、提示词、词表和算法版本。
- 按方剂族、同名方、加减方和药物高度重叠方分组，防止近重复方剂跨越训练与测试；
- 任何从测试集错误分析得到的样本只能进入下一版测试或训练周期，不能回写当前测试结果。

## 7. 当前待确定事项

1. 首个验证专科或病种群；
2. 首位名医及其可用材料；
3. 第二层按个人、流派还是著作组织；
4. 至少两名医学标注或评审专家的可用性；
5. 首版是否包含具体方药和剂量；
6. 首要目标用户；
7. 材料版权和患者伦理条件；
8. 论文采用回顾性、模拟还是医生在环研究。
9. 进入阶段六时可选的基础模型、部署资源和模型权重发布范围；
10. 哪些材料只允许检索，哪些材料届时允许生成训练样本或训练模型；
11. 阶段一至阶段五达到什么完成状态后，才触发后训练方案设计。
12. 西医兼容样本选择及其专家、指南与评价条件；
13. 三个初始逻辑 Agent 的最终职责边界，以及中医、西医和安全治理角色在什么条件下启用；
14. 矛盾矩阵、证明图、治疗算子和反事实任务在论文中作为核心方法、辅助方法还是工程组件。

LadybugDB、嵌入式运行和多包联合查询方向已经确定，不再列为待选数据库问题。后续仍需通过压测确定单库容量、逻辑分区时机和发行平台范围。
